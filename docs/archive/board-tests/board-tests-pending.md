## T152 board session (2026-11-01, Alex: "we measure tomorrow"): MultiCore update, flash protection, ESP32 inspect

Spec: [T152](specs/T152-update-and-flash-protection.md). Everything below is built and benched without the board (`tests/hostapp/run_txu.sh`, `run_flashlock.sh`,
`run_espinspect.sh`, the render bench); the steps are what only the board can prove. One session, in this order (S6 and S1 first: they need no lock). Nothing
here is run before the board has the host app of the run that carries T152; "the card" is the SD card with `/cores` and the `.txu` files.

**What to read back, and how** (all read-only; never power-cycle from a script, Alex does):
- *JEDEC ID, SR1, SR2 as the host saw them:* the host logs one line when it sets the lock: `[host] flash protection before the handover: flash 0x000000-0x3FFFFF
  protected, lock-down set (JEDEC ef4018, status 34 01)`. Read it from the F8 "Bug report" (`report/<date>.txt` on the card) or `GET /v1/report`, the
  last log lines. SR1 `34` = TB + BP2:0 = 101, SRP 0; SR2 bit 0 = SRL. On a board whose chip is not a W25Q128JV the line says `not a W25Q128JV: the flash is
  not protected` and the status bytes are 00 (the registers are not touched then).
- *Independent read of SR1/SR2 after the start (a second opinion, not the host's own log):* no tool for it exists in this repository. openFPGALoader's
  `--detect` prints the flash chip's JEDEC ID; a status register read needs an SPI frame (0x05, 0x35) over its spiOverJtag bridge, which nothing here
  sends. If the host's log line is not enough for Q5, a small `tools/dev/` script for that frame is the next thing to build, not a guess at the board.
- *sha of the flash regions:* `openFPGALoader -c usb-blaster --fpga-part xc7a50tfgg484 --dump-flash --offset 0x0 --file-size 0x220000 bit.bin` and
  `... --offset 0x220000 --file-size 0x1E0000 app.bin`, then `shasum -a 256 bit.bin app.bin` (check the option names with `openFPGALoader --help` if the
  installed version differs). The Blaster must be unplugged again before the power cycle (`docs/board-tooling.md`).
- Take the sha pair once before the session ("A") and compare after each step that says "unchanged".
