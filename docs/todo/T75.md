# T75: REU register window and turbo colour RAM read as on Gideon's core

Milestone M2, status 📅. Open (one line, as in the TODO table): Not built

## Description

Two open-bus differences from Gideon's core that T74's measurement found (2026-10-10, raw output
`tests/openbus/data/gideon_90f301c_*.txt`, history in [T74](T74.md)):

1. **REU register window.** With the REU on, Gideon's REU answers only `$DF00-$DF1F` (`$DF0B` reads `$FF`,
   `$DF80`/`$DFFF` the VIC byte). Ours mirrors the REU registers over all of `$DF00-$DFFF`. Where to change:
   `cores/icepi/c64_bus_arbiter.v`, the IO2 case (`4'hf`, REU select) and `pk_reu` (turbo look), both gated
   on address bits 7:5 = 0. Not checked: whether a real 1750 mirrors (VICE/real hardware); M1 rule
   "Gideon measured wins" picks Gideon's window.
2. **Turbo colour RAM read.** At 16 MHz Gideon's `$D800` read has the last CPU bus byte (`$D`, the operand's
   high byte) in the upper nibble; ours has 0 (`c64_turbo.v` fast path). At 1 MHz both have the VIC byte.

Also measured, no change planned: in turbo, Gideon's IO1/IO2 reads right after a write return the last CPU
bus byte (an echo); ours not measured in turbo.

Test: REU sim bench, CI, board `tests/openbus/openbus.py` with REU on and `--speed 16`, one REU program.
