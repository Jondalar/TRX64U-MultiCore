# T114 - Core logos

Spec: [T114-core-logos](../specs/T114-core-logos.md).

Milestone M3, status done. Open (as in the TODO table): none; the logos are packed into every .cor and drawn by the boot menu.

## Description

One recognisable 32 x 32 logo per shipped core (`cores/<id>/logo/`), packed into the .cor as the icon record and drawn by the host app's boot menu (T101 D5).

## History

- **2026-10-26, Apple silhouette:** Alex supplied the real monochrome Apple mark. The small icon is no longer assembled from a round ellipse; its own curved outline now carries the top notch, asymmetric shoulders, bite, leaf and lower lobes.

- **2026-10-26, padding inside the fixed icon record:** the `.cor` record and host slot stay exactly 32 x 32 RGB565, but the C= symbol no longer fills that box. It has about four output pixels of breathing room; the two wedges begin at the C's right edge instead of overlapping its ends.

- **2026-10-26, the C is a C:** the earlier generator made the C from two ellipses and cut its opening with a rectangle, which left artificial ends at 32 px. It now uses a real bold C glyph; only the two small blue/red wedges are separate geometry.

- **2026-10-26, canonical Commodore mark:** Alex supplied the blue/red Commodore wordmark reference. The 32 px platform icon keeps only its symbol: blue C plus upper wedge and the red lower wedge immediately below it, separated by the narrow gap of an equals sign; the `commodore` text is intentionally omitted at icon size.

- **2026-10-26, TRX64 cue:** the minimal TRX64 icon says `TRX`, not only `T`; it stays a single compact wordmark and does not add the model number or decoration.

- **2026-10-26, C= proportions:** Alex's enlarged screenshot showed that the two wedges dominated the C. They are now shorter and flatter while the C ring stays unchanged, matching the physical badge more closely at 32 px.

- **2026-10-26, one symbol per platform:** Alex rejected both the hard-pixel and softened-pixel variants: "normal logos in 32x32" should be reduced to `C=` for Commodore, `A` for Amiga, an Apple symbol for Apple, and equivalent minimal cues for the rest. Model names and numbers stay in the menu label, not inside the icon; the small icons are monochrome.

- **2026-10-26, controlled edge smoothing:** Alex found the first hard-pixel pass too different from the earlier visual language. The simplified 32 px motifs stay, but a supersampled edge pass and explicit RGB565 quantisation now soften curves and diagonals. No detailed tile, small footer or unreadable mini-label returns.

- **2026-10-26, true 32 x 32 icon family (Alex):** "TRX64 should have its own. U64 and C64U too. The rest may be based on the original platforms and their logos." (translated). The vector tiles remain as large previews, but the menu icons are separately authored small marks without a tile frame or miniature footer text. TRX64, Gideon's U64 and C64U have three different payloads; all shipped descriptors including the large A1200 and C128 are covered. `tools/core_logos/contact-sheet-32.png` shows the exact 32 px sources enlarged with nearest-neighbour scaling.

- **2026-10-21, decision: the host gate skips the logo folders too.** `tools/host_pin.sh` excludes `cores/*/logo/**` like `tree_key`, so
  `cores/trx64/logo/` does not count as a host change. Alex: "For now yes, we will surely have to build again at some point" (translated).

- **2026-10-26, 256 px logos and SVGs removed (Alex):** "die 256px logos können wegen mir weg und die SVGs dazu auch" (translated: "as far as I'm concerned the 256 px logos can go, and the SVGs with them"). `build.py` makes only `logo-32.png`, `icon.rgb565` and `contact-sheet-32.png`; no `rsvg-convert`. All `icon.rgb565` bytes unchanged (sha256 compared); `--check` and `gen_cfw_icons.py --check` pass.

- **2026-10-22, crisp 32 px icons (Alex: "re-render the PNGs for the logos to fit the resolution", translated):** `tools/core_logos/build.py` no longer downsamples the 256 px render with Lanczos (every edge became a grey that is in no palette). `render_icon()` renders the SVG at 8 x the icon size and decides each icon pixel from its 8 x 8 cell: pixels snap to the nearest palette colour first, the cell takes the most frequent mark colour if one covers 30 % of it, else the most frequent colour (so a stroke thinner than a pixel still gives a whole pixel). Every pixel of `logo-32.png` / `icon.rgb565` is now a palette colour. The 2048-byte icon record and the `.cor` format are unchanged. Limit of the source: the small lines of text (e.g. "ULTIMATE", the machine names under the marks) are 2-3 px high at 32 px and stay unreadable noise; only the big marks (C=, TRX64, 264, ZX, CPC, NES, apple, ball) read. A 48 x 48 set (for a bigger icon box) was not made: no variant needs it now (1280 x 720 does not exist, `docs/todo/T101.md`), and showing it would need a bigger icon record, which is Alex's decision. Old over new at 4 x: `scratchpad/resvar/logos32_old_over_new_x4.png` of the session.

- **2026-10-22, icon scale (Alex's board photos of the boot menu: "something is fundamentally off there", translated):** the picture was drawn 1:1 (no LVGL zoom; the layer is 960 x 540 and the pixel layer shows it at the whole factor 2, `PX_CTRL` 0x22 in `trx_lv_port.cc`, `host/pix_layer.v`) inside a 48 px wide grey box, so a 32 px picture had 8 px bars left and right (`hostui.cc` `build_row`, image at x 8). The box is now exactly the picture (32 px, `ICON_W`; 48 px stays the text tile's), the LVGL scale is set to 256 (1:1) explicitly. Render bench: `icon_no_bars` (the pixels around the found picture are the row background) and two controls (`bars`: box wider than the picture; `zoom`: LVGL scale 300) that must go red. The uneven pixel widths of the photo do not come from the app: layer, zoom and the x2 are whole numbers end to end, the output is fixed 1080p; what remains is the source (the 32 px derivative is a Lanczos downsample, so edges are blended grey values, not pixels) and the screen's own scaling of the 1080p signal. Text inside the logos ("ultimate") is about 3 px high in 32 x 32 and cannot be legible; a legible mark needs a 32 px design without text or a larger icon record (proposal, Alex's decision, nothing built).
