# T74: Unmapped I/O reads return the VIC's phi1 byte (open bus as on a real C64)

Milestone M1, status ✅. Open (one line, as in the TODO table): –

## Description

A CPU read of an I/O address that no device answers (e.g. $DE00-$DFFF with no cartridge using it) returns, on a real C64,
the byte the VIC fetched in the phi1 half before (nobody drives the data bus in phi2). VICE models it
(`vicii_read_phi1()`), TRX64 copies it (`trx64-core/src/full.rs:918`, `lib.rs:2248`: `unwrap_or(self.vic.last_read_phi1)`).
On our core the physical expansion port returned the last byte on its data lines: the FPGA drives D only in a write and
the cart only in a read, so a read no cart answers sampled what the bus had been left at (the probe's own `$A5`, or the
byte of the previous cart read). Found 2026-10-10: the trex_crt EasyFlash probe (write $A5 to $DF00, read it back) took
every cart for an EasyFlash (T57, fixed in the app). Gideon's core: not measured; the probe worked there.
