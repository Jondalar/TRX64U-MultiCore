# T85: Amiga (Minimig) core from NanoMig

Milestone M3, status done. Open (one line, as in the TODO table): Done: A500 runs (generic app, disk change from the menu boots); board confirmed by Alex 2026-10-28

## Description

An OCS/ECS Minimig core ported from MiSTle-Dev/NanoMig as the third core behind the T79 host (TREX-internal until Q1). Spec: [T85-minimig-core](../specs/T85-minimig-core.md). Biggest risk: chip RAM latency from DDR2 against the 141 ns chip bus cycle (D4).

## Board session 2026-10-16: two findings

- **No sound on the A1200: not the gateware.** Measured 2026-10-16 with `run_l2.sh`'s audio case and the
  A1200's three generics (`CHS_INIT=16 MEM_INIT=3 HDF_SECT=1`): `audio_l` is 2,048,256, the same tone the
  OCS power-up produces. Each generic on its own gives the same. The run is in `run_l2check.sh` now.
  T109 §5.1 has the table and what it leaves open.
- **The original note, kept for the record.** Both cores are built from the same file
  (`cores/amiga1200/core_sources.tcl` is `cores/amiga/core_sources.tcl` plus three generics:
  `CHS_INIT=16`, `MEM_INIT=3`, `HDF_SECT=1`), and the audio path is wired identically
  (`layer2_amiga.v:263`). So the cause is AGA or the 2 MB chip RAM, not the application. Next step
  without the board: `run_audio.sh` once with OCS/512K and once with AGA/2M.
- **Inserting a disk does not start it.** Alex: "wenn ich eine Disk einlege auf einem echten A500, dann
  bootet er die, weil er mitbekommen hat dass die eingelegt ist" (translated: on a real A500 inserting a
  disk boots it, because the machine noticed it went in). In the core `_disk_change` is only released by
  a step pulse for the selected drive when a disk is already present (`paula_floppy.v:610`), and
  `disk_present` is set by the mount pulse alone (`:965`). The application's `mount_adf` takes the drive
  away (`MOUNT=0`), fills the slot and puts it back (`MOUNT=1`) - a mount event, not the door of a real
  drive closing.
  Cause found 2026-10-23: the mount toggles were lost while the Freeze menu held `ce28` (History, 2026-10-23); the latch itself is fine.
