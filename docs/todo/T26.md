# T26: Boot chain: host firmware, guests loaded by the ESP32, golden stub

Milestone M2, status ❌. Open (one line, as in the TODO table): Won't do: we do not boot through the ESP32; the host loads cores by ICAP (T84)

Decisions: [ADR-0005 Golden stub: a never-writable minimal bitstream at 0x0](../adr/0005-golden-stub-boot.md).

## Description

Boot chain: host firmware in flash, guests (Gideon's C64U, TRX64, other cores) loaded into SRAM by the ESP32 over JTAG; new ESP32 firmware with rollback (docs/boot-chain-concept.md); the host needs its own receiver for the rocker's EVENT_MENU/RESET/FREEZE (SLIP on the WiFi UART) Golden stub (Alex, 2026-10-03): a minimal never-writable bitstream at 0x0 (RISC-V + SD/USB + SPI) starts first, offers a firmware file from SD/USB1, else MultiBoots into the main bitstream — no brick from a failed update Reference for the ESP32 side: GideonZ/1541ultimate issue #952 (noted in docs/boot-chain-concept.md).

See also: [docs/boot-chain-concept.md](../boot-chain-concept.md)
