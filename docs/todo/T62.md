## Design (2026-10-09)

One RTL bundle plus a small app change; every item is a few LUTs. Evidence below is from the code, not from comments.

**G04 safe mode.** `ConfigManager` (`config.cc:48`) and `init_flash_disk` (`blockdev_flash.cc:160`) read `U64_RESTORE_REG` once at boot and
act on `== 1`. `ultimate_sys` page 010 offset 0x02 (0x10100402) returns `"0000000" & restore_pin`. `restore_pin` is the pressed level
(1 = pressed) of the physical RESTORE pin OR the C64U keyboard's RESTORE (`bl_restore`), the same OR that feeds the C64's NMI
(`app_input.phys_restore`), synchronised into the 100 MHz clock in top.v. A live read is enough: nothing else writes the register and the
app's own NMI (`app_restore`, `C64_MODE` b4) does not touch the pin. Pin and `bl_restore` are the only RESTORE sources.

**G09 scan lines.** `C64_SCANLINES` (0x10180000, page 011 offset 0) is latched in `ultimate_sys` (reset 0; the app writes it from its
config at boot, default Enabled) and goes out as `scanlines`. `vic_scaler` darkens the last output line of every VIC line (4 lines per
VIC line at 50 Hz, 4/5 alternating at 60 Hz: the line where `acc_n >= acc_t`, i.e. the one after which `ln` advances) to 25 % brightness
(`rgb >> 2` per channel, mask 0x3F3F3F). Cost: one flag bit through the two pipeline stages, a 2-flop synchroniser and one AND/shift mux on 24
bits, about 30 LUTs. Only the C64 window is dimmed; borders of the 1920x1080 frame, the overlay (drawn after the scaler) and the still/stream
paths are untouched.

**G17 debug register.** `c64_top` raises `ext_dbg_we` for a write to $D7FF with I/O mapped (same `io_enable`/`bus_we` the UCI window uses).
`c64_core` registers it with the UCI bus event (phi2 falling edge) as `dbg_ev` + `dbg_data` in the C64 clock. top.v turns that into a
toggle plus held byte; `ultimate_sys` crosses the toggle with two flops and writes the held byte into page 101 offset 0 (0x10181800 =
`U64_DEBUG_REGISTER`) in the same process that serves the app's own writes (the C64's write wins a same-clock tie). So the register is the
last writer's value, from either side; `machine:debugreg` and `SOCKET_CMD_DEBUG_REG` read it back unchanged. A C64 read of $D7FF is not
implemented (the SID mirror answers it, as before). The write still reaches the SID mirror, which ignores it.

**G19.** `ETH_LED_YELn` (G13, output, low = on; Gideon's core drives it low at idle on the cabled board, boundary scan
`sample_no_cart.json`/`sample_with_cart.json`): on while a carrier (`RMII_CRS_DV` rising edge) was seen in the last 2^27 clocks of the
50 MHz RMII clock (2.7 s). That is the nearest thing to link the fabric sees without reading the PHY over MDIO; it goes dark on a cable with
no traffic at all. `IEC_RESET_I` (K13, same sense as the other `IEC_*_I`: 1 while the line is low; idle 0 in the scan) feeds
`drive_unit.iec_reset_n` (was tied to 1) as `not (reset_i and port on)` through the existing cpu_clk synchroniser, so a C64 RESET on the bus resets
drive A like on hardware. `IEC_SRQ_I`, `AUDIO_SPDIF`, `WIFI_*`, `RMII_IRQn`, `RMII_RX_ER`, `BOARD_REVn`, `UI_BUTTON` stay out (Alex).

**G21 IEC capability.** `g_capabilities` bit 5 (`CAPAB_HARDWARE_IEC`, 0x20) cleared (`28'h5E40222` -> `28'h5E40202`). What the bit gates in the
app (grep over `software/`, only `getFpgaCapabilities() & CAPAB_HARDWARE_IEC`): (1) `IecInterface::IecInterface` skips loading the microcode and
starting the "IEC Server" task, but leaves `available_slots`, `taskHandle`, `queueToIec` and the flags uninitialised (heap garbage on
`new`); (2) `create_ulticopy` returns before creating UltiCopy. It does NOT gate `init_iec_drive` ("SoftIEC Drive": the "Software IEC" task
category, the "SoftIEC Drive Settings" config page, bus id 11) or `init_printer` ("Printer": the printer config page and its Software IEC slave):
both are created unconditionally, so clearing the bit alone leaves their menus and registers a slave into an IecInterface with garbage
`available_slots`. App change (branch t62-gaps-app): both init functions return early without the capability, and the IecInterface
constructor initialises its members before the early return. UCI SoftIEC target answers "module not loaded" (`!iec_drive`) already;
`IecInterface::info` is NULL-safe. The printer's PNG writer (`mps_png.cc`) dereferences `iec_printer` only while printing, which only the
printer slave starts.
