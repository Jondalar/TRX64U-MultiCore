# T93: One core-application blueprint on the lean base

Milestone M2, status ✅. Open (one line, as in the TODO table): Done, reduced scope: superseded by T104; REST, net and the board check moved to T104

## Description

Core applications other than the C64's (Amiga T85, Atari 800 T88, Apple II T89, Spectrum T91, CPC T92) come from one blueprint ("meta-app") on the lean host-app base (T84 D10, D12): shared services once (ROM manager, media services, input sinks, Freeze and pixel-layer switch, REST subset, `.cfg` layering, handover), each core a descriptor (ID, ROMs, settings, tasks, file types, media, input, video, Freeze, REST). Menus are a whitelist generated from the descriptor. VC-20 (T83) and C16 (T90) may stay on Gideon's Ultimate app. Spec: [T93-core-app-blueprint](../specs/T93-core-app-blueprint.md).

## 2026-10-15 — the board, finally, and two defects it exposed
- The application image in a bundle was the `.app`, header and all; both blueprint cores executed their own
  load address and died in the trap handler. Fixed in `tools/build_coreapp.sh`; `cor_pack.py` now refuses a
  header there, with both controls in `tools/test_cor_pack.py` (spec 5.12).
- The rocker: the button read was Gideon's already, and his driver is now vendored in
  (`io/uart/dma_uart.cc`, `cmd_buffer.c`). What was wrong is **which** of his two bring-ups was copied:
  `Esp32::EnableRunMode()` is the module-control path and opens the link at 115200, while the module's
  firmware speaks 5 Mbit/s with CTS/RTS flow control (`my_uart.c:403-408`). `hw_rocker_init()` now follows
  `wifi_command_init()` (`wifi_cmd.cc:32-44`) instead. The loopback self-test is blind to a wrong rate (both
  ends share the divisor), so a second test came with the fix: a `CMD_IDENTIFY` to the module, whose reply
  proves the rate, the flow control and both directions - with `-DROCKER_WRONG_BAUD=1` as the control
  (spec 5.16).
- A core application must not inherit the machine's stop register, which lives in the host: `coreapp_run()`
  clears it. A core shifted in over JTAG is not a core the host handed over - the black screen that cost an
  evening was the partial load, not the application (spec 5.15). Both the menu keys and late-mounting media
  were solved in the host application and had not been carried over (spec 5.14).

- The Atari application ran on hardware: ROMs found on the stick, core released, Atari BASIC on screen.
