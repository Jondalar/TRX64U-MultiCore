- **2026-10-26, debug build (Alex: "build something to debug, onto the board, debug"):** reading of the cache found no certain logic fault (a store hit

  - `0x100060` (r/w, sys_clk, reset value 0 = cache OFF = today's behaviour): bit0 cache on, bit1 snoop on, bit2 ext-walk on, bit3 check mode (a would-be
    hit is read from DDR2 as well, the program gets the DDR2 word, a difference is counted and the first one latched), bit4 clear toggle (write 1 = counters
    and mismatch latch cleared), bits 15:12 select the counter. Turning bit0 on starts a full clear walk.
  - `0x100061` (r): the word selected by ctl[15:12]: 0 check mismatches (16 bit), 1/2/3 first mismatch (address, cached word, DDR2 word), else status
    (bit0..3 ctl as seen by the cache, bit4 walk busy, bit5 mismatch latched, 7:6 state). Hits and misses stay in the rv_tap snapshot (0x100040, upper 12 of 20 bits).
    (The first versions with more counters did not route: pb_l1 is full; this is the minimum.)
  - Board: `tools/trxdbg.sh dcache on|off|check|clear|stat|mask <bits>` (`stat` prints all counters; raw: `Dbg().write(0x100060, ctl | sel<<12)`, `read(0x100061)`).
    Reset value of `0x100060` is 0x0007 since 2026-10-27 (cache, snoop and ext walk on, check mode off); `dcache off` switches the caches off.

- **2026-10-27, 16-byte lines (design):** word-by-word filling through the 32-bit bus would cost the saved misses again (14.2 clocks per icache miss, one more per extra word), so the line
  comes on a side band: `mig_arb` keeps the whole 128-bit word of client 0's last read (`rline0`, ui_clk, written with `rdata`), `cpu_mem_bridge` copies it with the answer
  (`line`, `line_adr` = address[25:4], cpu_clk, valid from the clock of the dack until the next read answers), `top.v` -> `ultimate_sys` (`dc_line`, `dc_line_adr`) -> `rvlite_wrapper_dc` -> both
  caches. The buses, records and `bus_converter` are unchanged: the cache still asks for its word as before; when the answer arrives it writes the whole line (128-bit data RAM, one clock, tag
  per line) from the side band if `line_adr` is that read's line (otherwise only the word goes to the core and nothing is cached). Generics: `g_line_bits` of `rvlite_wrapper_dc`/`rv_dcache`/`rv_icache`
  (log2 of the words per line, 2 = 16 bytes default, 0 = the old one-word lines, which is also what the dcache bench uses). Snoop and ext-walk work per line (index = line); a store hit writes its
  lanes into the line. Large cores read the same VHDL list, so they get the same lines (BRAM unchanged: same bits, 2 RAMB36 per 8 KB). The bench `dcache` was not run.

- **2026-10-27, T135 D6 port lock (gateware, for the T135 notes on main):** `host/top.v` `port_lock` = not (JTAG 0x10002A bit 0 or the application's release bit); the application's bit is in `ultimate_sys` at the
  icap region +0x21 (write bit 0 = 1 releases; read back at +0x21; reset value 0 = locked, so every IPROG back to the host and every CPU reset locks). Locked: SLOT_ADDROEn/DATAOEn/ADDRDIR/DATADIR/IO1n/IO2n/ROMLn/ROMHn/BA
  = 1, PHI2 = DOTCLK = 0, the address/data/R/W lines idle, `slot_rst_o` = 1 (the port's RESET held low), whatever layer 2 drives; `SLOT_PWR` stays 1 (Q7). Separate from `core_decouple` (a swap with the lock released
  still gives RESET 0 as before). JTAG: write 0x10002A bit 0 = 1 releases; read 0x100029+1 = 0x10002A returns {port_lock, application bit, JTAG bit}. NOTE: with this gateware nothing reaches the port until the host
  application (or JTAG) releases the lock, so the application change (T135 D6: release after the core is loaded and out of decouple, never for the null core) must come with it; large cores carry `top.v` and need
  their core application to release it too (icap +0x21 = 1).
