# T132 - Updater bugs seen installing the MultiCore host from Commodore 1.1.0

Milestone M3, status ✅ done 2026-11-15. Open (one line, as in the TODO table): Done 11-15 (Alex: in builds for weeks)

## Origin
Board, 2026-10-26: `trx64host_update_6b8bea46_20261026.ue2` (main run 193, the MultiCore host + null core + boot application) started
from Commodore's firmware 1.1.0 (`commodore-110.cfw` from the boot menu), the tester path of `docs/board-tooling.md`. Alex (photo):
"the text at the top ** TREX still is not in the middle! - without USB it does not go. That is a real bug" (translated). Fix later.

## Bugs
1. **The title is not centred.** `vendor/gideon/software/application/update_u2p/update_trx.cc` (the line before the fix):
   `setup(C_TITLE "  ** TRX64 Ultimate Updater **\n" ...)` - two fixed spaces before a 28-character title; on 40 columns it needs 6
   (or a centring helper). Seen on the board: the title sits left of the centre.
2. **The backup does not take the SD card.** With the SD inserted (with far more than 7.5 MB free) and no stick, the updater stops at
   "Backing up the flash (7.5 MB) to USB/SD.." with "No USB/SD with 7.5 MB free. Insert one. Retry?"; with a USB stick inserted it
   goes on. Code: `backup_pass()` (same file, from ~line 912) walks the root entries whose name starts with "usb"/"sd" and asks
   `free_enough()` -> `FileManager::get_free()`; for the SD that returns an error or 0 clusters. Cause (found 2026-10-29, from the code): see History.
   (Was: not measured.) Candidates to check first: the SD's root name as the updater's
   FileManager lists it, a partitioned SD (only `Part0..` subfolders are tried when the medium itself fails), `get_free` on the SD's
   filesystem type (exFAT / FAT32 with an unknown free count) in the updater's build.

## Where it is fixed
Since T120 (2026-11-01) the updater is not in a submodule any more: `vendor/gideon/software/application/update_u2p/update_trx.cc` and
`vendor/gideon/target/u64ii/riscv/update_trx/Makefile` are our own files in this repository, and both fixes are in them (`UPDATER_TITLE`,
`title_in_colour`, `header_line`; the Makefile links `sd_card.cc`, `sdio.cc`, `sdcard_manager.cc`). There is no submodule pin to move. The older
line "fixed in apps/ultimate `t135-installer`" names the place the fixes were first written.
