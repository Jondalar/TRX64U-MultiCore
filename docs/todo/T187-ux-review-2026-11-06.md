## Findings, by severity

### S1 - the selected row leaves the visible area (reproduced)
- A1200 F5 Settings, 20 rows (probe `uxp-a1200-f5-end.png`): selection on row 19 "Hotkey: picture mode"; the pane shows up to "Hotkey: reset"; no row is marked.
  Header says "3-20 of 20". Drawn height of the window 448 px, room 378 px (70 px = 3+ rows too many). C128 (21 rows): 392 vs 378.
- Cause: the window size is computed with one-line rows (`rows_h / (trx_row_h(false)+1)` = 18 rows) but 7 A1200 rows are two-line (34 px, not 20):
  `coreapp/src/ui.cc:259-260`, `:337`, `:525-526`; `app/view/trxview.cc:484` (`trx_row_h`), rows built at `:544`. The window logic `trx_window` (`trxview.cc:980`) is height-blind.
- Concept: GMT:542 "Der Fokus ist jederzeit deutlich sichtbar. Beim Zurueckkehren bleiben Scrollposition, Auswahl ... erhalten."; README.md:56 state before actions.
- The other path (`screens.cc`) already does it right: units with heights (`unit_h` screens.cc:183-189, `window_first`); only the flat list in ui.cc is broken.
  This is why the C64 Machine tab (description record, screens.cc) is fine and the C++ descriptors (A1200, Atari, C128) are not.

## Proposal: target layout for the F5 Settings tab (generic, from `Setting::group`)

Pane in the screens.cc path (units with real heights), group headings as quiet dividers (UI-COVERAGE.md:84), rows 20 px, no per-row second line.

```
F5 <CORE>   [1 SUMMARY] [2 SETTINGS]
 MACHINE                                   (core's own rows without a group; marker "RESET" on at-next-reset rows)
   Kickstart file             Auto (3.1 first)   RESET
   Chip RAM / Slow RAM / Fast RAM / Chipset / Floppy drives / Floppy write protect   RESET
 PICTURE
   Picture / Scale / Smoothing            (group "video")
 SOUND
   Volume                                 (group "audio")
 INPUT
   Joystick ports
   Hotkeys >                              (ONE row that opens a sub-page: modifier + 6 keys; group "input")
 STORAGE / FILES                          (only where the core has slots)
   Persist medium mounts                  (group "system", from F8)
   Home directory / Enter home on startup (group "system", from F8)
```
- Order of groups fixed: Machine, Picture, Sound, Input, Storage. Rows of a core that name no group are Machine. "LED Load Indicator" belongs to Input/Storage per core (descriptor sets the group).
- Hotkeys: one row "Hotkeys: C= + CTRL >" opening a page (same page type as a tab); keeps the main list at ~16 rows on every core and removes the 7-row block. (Alternative: leave 7 rows but under the INPUT heading.)
- Home directory + Enter home + Persist: they are "files" settings; keep them with one place. Proposal: F5 Settings under STORAGE (a user changes them together with the media), and F8 keeps only machine/host actions. (T180 D2/D10 put them on F8; this moves them - Alex decides.)
- F8 System ("Expert" today) target: group SYSTEM ACTIONS (Restart core, Return to host menu) / NETWORK (WiFi On/Off + line, one row, state value: "On - 192.168.x.x" or "Off") / SUPPORT (Bug report) / DANGER ZONE (Reset to host defaults, last row, confirmation). Initial focus on row 0 that is not destructive.
- Concept alignment: the concept's F6 Settings area (Video/Audio/Input/Network tabs, NAVIGATION.md:34) does not exist in the core app. Groups on F5 are the smallest step; the full move is a decision for Alex (question 1).

## Rules to adopt (proposal)

List scrolling
1. The window is computed from the real heights of the rows (sum of `trx_row_h(two_line)+1` + headings) - never from a row count. One function for build, signature and in-place pass (ui.cc:259, :337, :525).
2. The selected row is always completely inside the pane; after a scroll it is the last or first fully visible row, never partial. PageUp/PageDown move by the window, Home/End jump.
3. A heading is never the last line of a window (take it into the next window) and is never selectable.
4. Scroll indicator: "above" / "below" count at the pane's edge ("5 more"), position text no longer overlaps row 1 (own line below the title or in the foot line).
5. Returning to a tab or from a sub-page restores selection and first row (GMT:542).
6. One-line rows by default; a second line only for an explanation the person needs now (unavailable reason, error), never for a repeated flag.

Toasts / status
7. One channel: a message is a toast OR the pane's status line, never both (menuctl.cc:1671).
8. The toast lives in the foot line of the pane (above the key legend, centred on the pane, not on the canvas) and the list reserves that line while the toast stands, so it can never lie on a row. Alternative: the toast replaces the status line in place.
9. Lifetime 2 s (TOAST_MS), no stacking; a new line replaces the old; a value toast (volume) shows the value with a small bar, text "Volume 105%" (volume.cc:7-8 runs 0..200% in 5% steps, so 105% is valid).
10. Over F1 Home / panels the same foot-line rule (no overlap with panel buttons).

## R4 addendum (coordinator/Alex): generic rows land in different places per core

Rule in code: `menutree.cc:164-171` (F5 Settings) and `:179-195` (F8 System). Default-route cores (no description record: every core except trx64u/C64) get home + persist rows ONLY on F8
(`persist_is_generic`/`home_is_generic` are excluded from TW_SETTINGS unless the tab names `groups`, :167; added to TW_SYSTEM at :185). A core with a description record (only
`coreapp/cores/trx64u/menu.toml` on main) places rows by `Setting::group` via `group_in_tab` (:71-88).

Where each generic row lands today (probe on main, 452879249, plus code):
| row (group)                         | default-route cores (A1200, Atari, C128, Apple II, NES, ...) | C64 / trx64u (record) |
|---|---|---|
| Home directory, Enter home ("system")| F8 System/Expert, after WiFi                                 | F8 System tab (groups expert, system; menu.toml:194) |
| Persist medium mounts ("system")    | F8 System/Expert                                             | same F8 tab if the record lists group system |
| Picture/Scale/Smoothing ("video")   | F5 Settings, flat, no filter (no group test on default tabs) | F6 Settings > Video (menu.toml:150) |
| Volume ("audio")                    | F5 Settings, flat                                            | F6 Settings > Audio (:158) |
| Hotkey rows ("input")               | F5 Settings, flat (7 rows)                                   | F6 Settings > Input (:166) |
| WiFi (EK_WIFI, not a Setting)       | F8 System/Expert (menutree.cc:183)                           | F8 (record node; menu.toml:1064-1091 shows state on F6 Network) |

So by the code Home Directory is on F8 for the A1200 as well, not F5: the probe (`uxp-a1200-f8.png`) shows Enter home on startup / Home directory on F8 and neither on F5 (20 rows).
The commit that routes them (65e39b660, 2026-11-06) is an ancestor of package a9ef1237, so the package has the same rule. The photo of Home Directory on A1200 F5 therefore
cannot be explained from main: either a different build was on the board, or the row was seen elsewhere. Needs one board look (F8 vs F5 of the A1200) before anything is changed.
What does differ per core is real: C64 has the concept's F6 Settings area (Video/Audio/Input/Network); every other core has only F5 Settings + F8 Expert, and there Picture/Volume/Hotkeys sit flat on F5.

Proposal (same for every core, independent of record or default route): ONE placement table in code, keyed by group, not by tab type:
video, audio, input -> Settings area (F6 tabs where the area exists, else F5 Settings group headings); system (home, persist), wifi, host actions -> F8. The default route should get the
same group-to-tab mapping as a record (generate the default skeleton with groups), so menutree.cc:167/:185 special cases disappear. Test: for every core in core_table, assert each generic
row key lands in the same area key (F6/F5 vs F8) as in the C64; a core listing the row elsewhere fails.
