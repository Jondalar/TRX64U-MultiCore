## What is built
- `host-app/software/hostapp/webui.{h,cc}`: the page, the JSON, the five routes and the mailbox.
- The transport is Gideon's MicroHTTPServer (`server.c`, `http_protocol.c` out of the submodule the
  tree already carries as a symlink) with **our** dispatch - not his `middleware.c`, which is wired to
  his application API (D1).
- One writer (D2): the web task only queues; `web_pump()` in the UI loop applies, saves and refreshes
  the snapshot both renderings come from.
- The A key and the browser share `add_found_at()`, so a refused bundle is refused the same way.
- Plain HTML forms, no JavaScript (D3). Port 80, no authentication, said out loud (D5).

## What is measured
- `tests/hostapp/test_webui.cc`: 77 checks - the page shows the menu, the found bundles, the media and
  the picture, escapes a name, cuts rather than overruns; the JSON names the same facts and survives a
  quote in a name; every route and every refusal (400, 409, 404). Control `web_ignores_form`: a route
  that ignores the form body must fail it.
- `tests/hostapp/render/render.cc`: a command from the network through the real UI task - the picture
  applied and written, an entry removed, a bundle for another contract refused (54 checks).

## Open
- The board step (in [board-tests-mc](../archive/board-tests/board-tests-mc.md)): a browser on the same network, the page, a start from it.
- `GET /` is answered for every path that is not `/v1/...`, so a phone that types nothing lands on the
  page. Worth revisiting if the API grows.
- One POST at a time (§5.1). Fine for a rescue page; not fine if this ever becomes a service.
- The core application still has no REST (T93 D12); the routes here are the shape it would take.
