# T103 — A second C64 core that is Gideon's set, not ours

Milestone M3, status closed. Open (one line, as in the TODO table): Dropped: large cores start from the menu; a vanilla C64 on the MultiCore host is not needed (use the original)

Spec: [T103-c64u-vanilla-core](../specs/done/T103-c64u-vanilla-core.md). Asked for by Alex on 2026-10-15:
a C64U core with Turbo, UCI, UltiSID (reSID8) and the rest of the stock set, and without the ring,
the TRX64 engine and the debug path - "a second C64 core that is closer to Gideon's vanilla in terms
of the feature set" (translated). The application side leans on the `trex/main` branch of
`1541ultimate_fw`.

The switch exists already: `TRX_FEATURES` unset means every optional block is on (`ci/lib.sh`
`feat_on`), and it is part of the gateware key, so two cores with different sets are two cache
entries. The open question is area: the reference core is the tightest in the partition at WNS
0.030 ns, and this core adds blocks rather than removing them.
