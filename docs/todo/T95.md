# T95 — NES core in the host/core split

Milestone M3, status 🔨. Open (one line, as in the TODO table): Board: NES switches to 720p and fills ~93 % of the height (T107 picture per core)

Spec: [T95-nes-core](../specs/T95-nes-core.md). Added to the core list by Alex on 2026-10-13: "put NES on the core list" (translated, with
T96 for the SNES; the list and the reasoning are in [T79](T79.md)). Asked for as a spec and an overnight build on 2026-10-15:
"then take NES on as a spec please and build it overnight too! How we handle the pad I do not know yet, but never mind for now."
(translated).

Source decided by Alex on 2026-10-15: **NES_MiSTer** (GPL v3), "the MiSTer NES core, definitely. GPL is great, after all"
(translated) - spec D12. State on the branch `t95-nes-mister` (M1-M5, each a commit): the machine of NES_MiSTer at 49a0a66, vendored and made
by a counted generator (`tools/nes_gen.py`; the 6502 converted from VHDL by GHDL in a container); our glue (clock enable of the 21.477 MHz master
clock on the 100 MHz clock, cartridge in the DDR2 behind line caches that hold the machine on a miss, window, INES header registers, frame
writer, sound, PAL register); ten mapper modules with a bench each; Verilator benches with negative controls (`cores/nes/sim`, `ci/sims.txt`:
`nes`, `nes_maps`, `nes_l2`). **Open:** the first Vivado run (timing of the clock-enabled machine, the PPU's area, the SystemVerilog the tools
must take; spec 5.10, 5.11), the controller (section 4), the application and the board (T93), the mappers that are not built (prices in 5.10).

- **2026-10-15, M3 (branch t95-nes-mister):** PRG and CHR ROM behind the DDR2 (`CART_BASE`) with 4 KB / 8 KB direct mapped line caches; a miss holds the whole
  machine (clock enable), 0.96 % held on the instruction bench at 293-693 ns per read. Window rewritten (variable latency, 2 MB space). New benches: bank
  switching (UNROM, CNROM), window-write invalidation, three mutants that must fail. Spec 5.9.
- **2026-10-15, M2 (branch t95-nes-mister):** the MiSTer machine runs in Verilator with the T65 converted by GHDL: frame, NMI, sprite DMA, sound,
  window, Freeze through pausecore (12.4 ms to halt, resume +1 master tick), layer-2 edge; benches adapted, mutation fails. Spec 5.8.
- **2026-10-15, run 44: the NES routes.** No `12-4739` left, WNS +0.100 ns after placement and **+0.106 ns after the
  route** with 0 failing endpoints of 40,928, hold +0.052 ns, `pr_verify passed`, and **13,114 of 18,000 LUT in pb_l2
  (72.9 %)**, 5,935 FF, 11 BRAM tiles. The densest core in the partition so far. Spec 5.17.
- **2026-10-15, run 43: the same constraints, applied at synthesis and dropped again at implementation.** Vivado writes an
  out-of-context design's constraints out as the command text and evaluates the `get_cells` filter a second time, scoped to
  the cell, where NAME begins with `l2/`: six `CRITICAL WARNING: [Vivado 12-4739] ... No valid object(s) found`, WNS -8.969 ns.
  Every pattern now starts with `*`; `ci/bitstream_layers.sh` fails a core whose log holds that warning (negative control in
  `ci/test_layers_flow.sh`). atari800 routed in the same run at WNS +0.114 ns and is cached. Spec 5.16.
- **2026-10-15, run 46: the pad routed.** 32 LUT and 80 flip-flops more in synthesis, WNS **+0.114 ns**
  (better than run 44's +0.106), hold +0.048, `pr_verify passed`, partial 1,319,290 bytes, no
  `12-4739`. The other six cores came from the cache, untouched. Spec 5.19.
- **2026-10-15, the pad (asked for by Alex):** both NES ports are driven from the C64's own hardware - directions and A from
  `c64_joy1/2`, B = space / right shift, Select = F3 / F7, Start = F1 / F5 ("map the C64 joystick + the keyboard sensibly?
  F1 = Start, F3 = Select", translated; B on space is his answer to the one open point). `cores/nes/trx/nes_pad.v`: latch while
  `joypad_out[0]` is high, shift on the falling edge of `joypad_clock`, order A, B, Select, Start, Up, Down, Left, Right, ones
  above the eight buttons. No host change, no contract version, no application part: the lines are contract inputs. Bench
  `run.sh pad` green with the `padorder` mutant failing as it must. Spec 5.18. A USB gamepad stays out: the firmware's HID driver
  decodes keyboards and mice only.
- **2026-10-15, run 42: synthesised (12,139 LUT, 5,933 FF, 11 BRAM), and the timing constraints were never applied.**
  Vivado's XDC parser drops every Tcl control command, so each `set_multicycle_path` of `nes.xdc` sat in an `if` that was
  thrown away: the machine was timed at one clock, WNS -8.563 ns after placement, the route diverged (overlaps back up to
  12,825) and was still running after 2 h. Moved to `cores/nes/nes_timing.tcl`, sourced after `synth_design`; `ci/lint.sh`
  now refuses a `.xdc` with a control command (negative control proven). Spec 5.15. The route is still unmeasured.
