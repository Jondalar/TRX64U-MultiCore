# T25.1 — Clean-room SID engine (UltiSID replacement, up to 8 SIDs)

**Status:** spec 2026-10-02; built on branch `t25-sid` (M1-M4: model, RTL, 8 SIDs, in
`c64_basic`), not yet on the board. Decisions: §4a, measured cost: §5. **Task:** TODO.md T25 (overview:
`docs/specs/T25-cleanroom-multisid.md`). **Replaces:** the reDIP SID in `cores/icepi`
(`c64_redip_sid.v`, `c64_redip_sid/`). **Feeds:** T25.3 (`T25.3-lp-filter.md`, decimation to
48 kHz). **Shares with:** ARCH (`ARCH-lean-state-access.md`, SID rows of the state bus),
T20 (snapshot/restore), T12 (mute on the machine pause).

**One sentence:** one time-multiplexed pipeline computes up to 24 voices and 8 filters per
C64 cycle from state held in RAM, answers the app's UltiSID registers (addresses, split,
filter curve tables, combined waveforms, resonance, digi level, voice levels), and hands one
sample per SID per C64 cycle to the mixer.

**Clean-room rule.** Written without opening Gideon's `fpga/sid6581` (UltiSID) VHDL, locally
or on the web. Sources: the app's code (what it writes and reads), Gideon's public user
documentation (no VHDL), data sheets, reSID/reSIDfp, reDIP SID and other open cores, our own
measurements. Every source is listed in §6 with its licence.

All app citations are `path:line` in `software/ultimate-app` at submodule commit `25568658`.

## 1. What the block does for the app and the user

### 1.1 What the user sees

- Menu "UltiSID Configuration" (`software/userinterface/commodore_menu.cc:55`) and "SID
  Addressing" with a visual address editor (`software/u64/u64_config.cc:418-428`).
- Two UltiSIDs. Each can be **split** into 2 or 4 SIDs on extra address lines, so the app
  addresses up to **8 SIDs, 24 voices, 8 independent filters**. Gideon's public manual
  describes exactly this (GideonZ/1541u-documentation `config/multi_sid.rst`: "In total 8
  SIDs, thus 24 voices and 8 independent filters"). The LED strip and Bling board read the
  envelope levels of all 8 (`software/u64/led_strip.cc:55-56` names "UltiSID1-A".."UltiSID2-D",
  `:333-335` reads `C64_VOICE_ADSR(sidsel * 4 + 0..2)` with `sidsel` 0..7).
- The SID player's autoconfig maps tunes onto UltiSIDs (`u64_config.cc:1979-2010`, slots 2/3
  and 6/7 are the emulated ones, `:1884-1892`); UltiSIDs report "either 6581 or 8580"
  (`GetSidType` returns 3) and `SetSidType` does nothing for them (`:1966-1977`). **There is no
  model register per UltiSID:** the model is what the filter curve and the combined-waveform
  setting say.

### 1.4 Other writers and readers

- **Mute around the freezer:** the app zeroes the first 8 bytes of both mixers instead of
  touching the SID (`u64_config.cc:1329-1366`); the SID engine itself is not muted by the app.
- **Freezer `$D418` write:** the app still writes the SID volume while freezing (comment and
  code at `:1329-1345`); that write steps the 6581 DC offset (§3.5).
- **Socket detection reads `$D400-$D7FF`.** Our `ultimate_sys.vhd` already makes these reads see
  no SID (`designs/c64_basic/ultimate_sys.vhd:775-777`), otherwise the app takes the internal
  SID for a socket SID. Keep that behaviour for app DMA reads; C64 CPU reads must see the
  UltiSID.
- **UCI "get SID info"** reports the two UltiSID bases/masks (`control_target.cc:420-440`).

## 3. Required behaviour

### 3.1 Instances and decode

- 8 SID instances `s = 4*u + p`, `u` = UltiSID 0/1, `p` = split part 0..3.
- Per C64 bus cycle with an I/O address `A` in `$D000-$DFFF` (I/O visible) and `u` in 0/1:
  `hit_u = ((A[11:4] & MASK_u) == BASE_u)`. The base is compared **unmasked**: a base bit set
  where the mask is 0 never matches, which is how `UNMAPPED_BASE` = 0x01 with mask 0xFE
  switches a SID off (`u64_config.cc:203-204`). This reading is inferred from the app (it
  clears base bits together with mask bits in `fix_splits` `:1276-1282` and `auto_mirror`);
  verify on a real U64/C64U (§4, Q1).
- Split part `p` = the address bits named by `C64_EMUSID_SPLIT`, packed LSB first (A5,A6 →
  p = {A6,A5}; A5,A8 → {A8,A5}; A7,A8 → {A8,A7}; one bit → p = 0/1). The app clears those
  bits from base and mask (`fix_splits`), so all parts hit.
- Register index = `A[4:0]`. Overlap order when two decodes hit (UltiSID 1 vs 2 vs sockets):
  Q2.
- Writes reach the instance's register file. Reads return: `$19/$1A` POTX/POTY, `$1B` OSC3,
  `$1C` ENV3, all other registers the SID's internal data-bus value with its decay (reSID
  `bus_value`/`bus_value_ttl` behaviour), per instance.
- POT: the paddle/mouse inputs of the core (`C64_PADDLE_EN`, `C64_PADDLE_1_X`..`C64_PADDLE_2_Y`, `software/system/u64.h:121, 139-142`; paddle work
  elsewhere) feed only the instance(s) at the standard $D419/$D41A address; other instances
  read 0xFF (reDIP does the same for its SID 2).

### 3.2 Per-voice digital behaviour (target: bit-exact to reSID/reSIDfp)

Phase accumulator 24 bit, sync and ring modulation chain inside each SID, test bit (holds and
resets the accumulator and the noise LFSR), the 23-bit noise LFSR clocked by accumulator bit
19 with its write-back from combined waveforms and the 8580/6581 reset/lock behaviour, pulse
comparator, triangle/saw/pulse/noise and the four combined waveforms (§3.3), the ADSR: 15-bit
rate counter with the rate table (including the rate counter wrap "ADSR bug"), the
exponential counter breakpoints (255/93/54/26/14/6), the 8-bit envelope with the freeze at
zero, attack/decay/sustain/release state machine, OSC3/ENV3. Source of truth: reSIDfp (cycle
exact, GPL-2+) as the golden model; differences between reSID and reSIDfp are listed in the
test plan, not guessed.

### 3.3 Combined waveforms

- `C64_EMUSIDn_WAVES` selects the 6581 or 8580 tables for all parts of UltiSID n.
- Tables: `_ST`, `P_T`, `PS_`, `PST` for each model. Options, in order of preference:
  1. Generate them at build time from reSIDfp's parametrised model (GPL-2+; documented
     parameters per model) into `.mem` files; P_T and PST indexed by the triangle-folded
     accumulator (2048 entries), PS_ and _ST by 12 bits. Data, not code.
  2. reSID's sampled `wave*.dat` (GPL-2+, sampled from real chips).
- Pulse-down/floating DAC input effects (reSIDfp "waveform DAC floating") follow reSIDfp.

### 3.4 Filter

- One state-variable filter per SID (LP/BP/HP, voice routing, voice 3 off, ext in = 0 on the
  C64U), Chamberlin form as in reSID/reDIP: `vhp = ... - vlp - vi + q*vbp`,
  `vbp += w0*vhp`, `vlp += w0*vbp`, once per C64 cycle.
- **Cutoff:** `w0 = curve_u[FC >> 1]` from the app's table of UltiSID u (1024 entries for an
  11-bit FC, so one entry per two FC values; whether the hardware interpolates the odd
  values: Q3). **Working hypothesis** for the meaning of the 16-bit value: `w0 = 2*pi*fc /
  f_phi2` in Q0.16, because then the scaled 8580 Lo table ends at 5118 → 12.4 kHz and 8580 Hi
  at 6685 → 16.2 kHz at 985 kHz, which brackets the 8580's documented ~12 kHz top. Must be
  measured (Q3) before it is fixed.
- **Resonance:** 4-bit RES → 1/Q from one of two tables, chosen by `C64_EMUSIDn_RES`. Table
  shapes: 8580 `1/Q = 2^((4-res)/8)`-style curve and a weaker 6581 curve as in reSID;
  "Low"/"High" mapping to curves: Q4.
- **6581 distortion** (reSIDfp's nonlinear op-amp/VCR model) is **not** in phase 1. Phase 1 is
  the linear SVF with the 6581 curve; phase 2 may add a cheap distortion approximation if
  listening tests ask for it.
- Filter state: two 20-bit integrators + the volume/mode register per SID.

### 3.5 Output per SID, digis

- Mixer per SID: `(vd + vf) * vol` (vd = direct voices, vf = filter output) as in reSID, plus
  the **DC offset** that makes `$D418` digis audible: the 6581 voice DC and mixer DC
  (reSID `voice_DC`, `mixer_DC`) scaled by `C64_EMUSIDn_DIGI`: Off = 0, Low/Medium/High =
  1/4, 1/2, 1 of the 6581 value (proposal; Q5). With the 8580 waves selected, "Medium" still
  gives audible digis, as users expect from the U64.
- 6581 DAC non-linearity for waveform, envelope and cutoff (reSID `dac.cc` 2R/R ladder model,
  reDIP `dac_6581_*.mem`): phase 2 for waveform/envelope; the cutoff DAC is already inside the
  app's 6581 curve.
- C64 board output stage (reSID `extfilt`: ~16 kHz 1-pole LP, ~1.6 Hz HP): LP in T25.3's
  decimator design, HP as the DC blocker in T25.3.
- One signed 20-bit sample per SID per C64 cycle to T25.3, plus a per-UltiSID sum (parts A-D
  of UltiSID n share mixer channel n: the app maps slot `& 3` to the channel,
  `u64_config.cc:2045-2054`).

### 3.6 Clocking, pause, state

- Engine clock: 2 x dot4x (63.06 MHz PAL, phase-locked to the C64 clock, 64 clocks per C64
  cycle) is the proposal; dot4x alone gives 32 clocks for 24 voices + 8 filters, which is too
  tight with one DSP per pipeline. The sys clock (100 MHz) needs a CDC for every bus write and
  breaks cycle alignment with the CPU; avoid.
- The engine advances only on C64 cycles the machine actually performs (the `gate_ce` of
  `c64_core.v`); on the machine pause it stops, so T12 freeze, T20 restore and T21 single step
  see a consistent SID.
- **All per-voice and per-SID state in RAM** (LUTRAM or BRAM), read at the start of a step and
  written back at the end. ARCH capture/restore is then a RAM copy through a second port, which
  also settles ARCH §14 item 3 (voices 1-2 audio state restored at no LUT cost).
- Register writes land in the register file in the CPU's phi2 cycle; the pipeline samples
  them in its next pass (reDIP takes writes in the first pipeline cycles for the same reason).

## 4. Open questions

1. Base compare unmasked (UNMAPPED_BASE trick) and behaviour for bases in `$DE00-$DFFF`
   (cartridge I/O area: who drives the bus, interplay with T16 cartridges)? Measure on a U64.
2. Overlap priority between UltiSID 1, UltiSID 2 and socket decodes; and whether a CPU read
   of an unmapped `$D400` returns open bus (VIC last byte) or something else.
3. Filter curve table meaning: index `FC >> 1` or interpolated, and value scaling. Plan: on a
   U64/C64U with Gideon's firmware, sweep FC with white noise, LP mode, one curve at a time,
   record the audio stream, fit fc(FC). Our own measurement; no VHDL.
4. Resonance "Low"/"High": which two 1/Q curves.
5. Digi level mapping (Off/Low/Medium/High → DC fraction), measured the same way.
6. Do split parts A-D get their own pan on the U64, or exactly the UltiSID channel? (app code
   says channel `slot & 3`; confirm by listening/recording.)
7. Licence: phase 1 written from reSIDfp behaviour (GPL-2+, compatible). Keep reDIP
   (CERN-OHL-S v2) as a fallback build option until the new engine matches it? CERN-OHL-S and
   GPL-3 mixing in one published bitstream is unsettled (T25 overview, docs/specs/T25-cleanroom-multisid.md).
8. Accuracy level for 6581: linear SVF + curve (phase 1) is what most FPGA SIDs do; is
   reSIDfp-class distortion wanted later?

## 4a. Decisions (as built, 2026-10-02, branch `t25-sid`)

Taken with the proposals above where there was one; the measurements of §4 can still overturn
them. Code: `cores/trx_sid` (model, RTL, tables), benches `designs/c64_basic/sim/sid`.

| # | Question | Decision |
|---|---|---|
| D1 | Engine clock (§3.6) | 2 x dot4x = 63.0556 MHz, a second output of `mmcm_sys` (re-planned to D = 3, M = 56.75, dot4x /30, 2x /15: the same 31.5278 MHz dot4x, now with an integer divider, edge-aligned). Not gated: a pass starts on a toggle that the C64's `phi2_n` (with the machine's gate) flips, so the engine runs exactly one pass per executed C64 cycle and idles while the machine is paused; an interrupted cycle's pass still completes, the state in RAM is always whole between passes. |
| D2 | Pass timing and reads | The CPU op of cycle N is latched at its `phi2_n` (clk) and taken into clk2x registers when pass N+1 starts (`op_tgl` synchronised into clk2x first); the pass is a pipeline (stage A in three clocks, the waveform tables with an output register, filter/mixer/bus value F0-F8 per SID, every RAM read and multiply followed by a register for 63 MHz) and is done after ~46 of 64 engine clocks. The read-back registers are copied into clk registers every C64 clock, so a read in cycle N+1 sees pass N+1 and every clk/clk2x crossing is register to register. This is reSIDfp's order (write, then clock, then read). |
| D3 | Q1 base compare | Unmasked: `({A11..A4} & MASK) == BASE`, so `UNMAPPED_BASE` (bit 0 outside the mask) switches an UltiSID off. Only `$D400-$D7FF` is decoded (the arbiter's SID select): a base in `$DE00-$DFFF` gives no SID until the arbiter and T16's cartridge I/O get an arbitration for it. |
| D4 | Q2 overlap, unmapped | UltiSID 1 wins when both hit; an access in `$D400-$D7FF` that no UltiSID takes reads the open bus (the arbiter's last bus value, `sid_hit` low). |
| D5 | Q3 curve table | `w0 = curve_u[FC >> 1]`, no interpolation; meaning Q0.16 of `2 pi fc / f_phi2`: `dVbp = (w0 x Vhp) >> 16`, `dVlp = (w0 x Vbp) >> 16` (reSID 1.0's linear 8580 form). |
| D6 | Q4 resonance | `1024/Q` tables: RES "Low" = reSID 0.16's `1/(0.707 + res/15)`, "High" = reSID 1.0's 8580 table `2^((4 - res)/8)`. |
| D7 | Q5 digis | Every voice adds the 6581 voice DC of reSID (`0x800 x 0xFF`) scaled by DIGI: Off 0, Low 1/4, Medium 1/2, High 1, for both WAVES settings; no separate mixer DC. |
| D8 | Model per UltiSID | `C64_EMUSIDn_WAVES` selects the whole chip behaviour of reSIDfp: combined-waveform tables, 6581 MSB pulldown, test-bit shift-register reset and floating-DAC fade times, the 8580 OSC3 pipeline, bus-value lifetime, waveform zero level (0x380 / 0x800). |
| D9 | Combined waveforms (§3.3) | libresidfp's computed tables (AVERAGE), indexed by the input value (so noise combinations are exact too), top 8 bits; deduplicated in 8-entry blocks: a 4096 x 9 directory and 4096 x 8 data, 2 RAMB36 for both models. Low nibble 0. |
| D10 | Output scaling | Filter states 25-bit, saturating; per SID `sat20(((Vnf + Vf) x vol) >> 7)`; per UltiSID the four parts summed and saturated. |
| D11 | /RES | Power-on state for everything (reSIDfp keeps accumulators and envelope counters over a reset). |
| D12 | POT | One 512-cycle counter (256 discharging, then counting until the line is charged) for `$D419/$D41A` itself; every other instance and mirror reads 0xFF. |
| D13 | Oscillator sync | Evaluated every cycle, gated the way reSIDfp's `voiceSync` fires (only in cycles where the MSB of a voice not in test, whose follower syncs, rises). |
| D14 | Q6 split pans | Parts A-D share their UltiSID's channel (the app's `slot & 3`). Commit M4 mixed both UltiSIDs to mono into the old CDC/DC-blocker path; T25.3 (`trx_audio`, same branch) replaced that with the app's gains and pans and the decimator. |
| D15 | Q7 reDIP | Kept as a build option: `SID_REDIP=1` in the environment of `designs/c64_basic/build.tcl` (`c64_top.v` `ifdef SID_REDIP`). |
| D16 | Q8 6581 distortion | Not built (linear SVF only). |
| D17 | State access | `trx_sid_engine` port `st_*` (word-addressed, between passes): voice records, register file, filter state, bus value. Not wired to the state bus yet (ARCH A2). |

**Deviations from reSIDfp** (digital part, measured by `sim/sid/run_m1.sh` against libresidfp
`dcf6b8ac`, 14.8 M cycles per model): none on the 6581 settings; on the 8580 settings OSC3 can
differ in bit 4 for one cycle right after a waveform change into pulse+triangle (the PT table
is indexed by `wv >> 1`, the previous cycle's saw value can be odd). Combined waveform outputs
differ in their low nibble by design (D9).

Device: Artix-7 50T, 32,600 LUT, 75 BRAM tiles, 120 DSP. Today ~23.7k LUT (task figure;
report of 2026-10-02 00:12 says 22,317 = 68.5 %), 56.5 BRAM tiles (75.3 %), 14 DSP. 80 %
ceilings: 26,080 LUT, 60 BRAM tiles. After the swap: LUT ±0..+300, BRAM 53 tiles (70.7 %).
**BRAM, not LUT, is the tight resource**; the SID swap helps it. If the estimate grows past
1,800 LUT, the fallback is 4 SIDs (12 voices, one UltiSID split in 2 + UltiSID 2), which keeps
the pipeline at dot4x.

~23.7k to ~24.7k LUT (76 %, ceiling 26,080) and from 56.5 to 53 tiles. The estimate above
missed the stage-A logic (write effects, envelope pipelines, test-bit timers: reSIDfp's
details cost LUTs) and the 8-stage pipeline records (111 bits each).
