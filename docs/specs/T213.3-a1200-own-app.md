## §1 The problem

The matrix (T239.5) builds a core that has moved to the SDK in 13 steps, from lint to delivery. The VIC-20, a partial core, went
through it on 2026-11-24 (run 45481704917). No large core has moved. The A1200 is the first (T239.3 D3), and it is the pattern for
the large cores of other repositories (trx64u, trx64g; TRX64-Ultimate's U20).

What is true today (read from the code, `t239.3` at `25a9b99cb`):

- The A1200 is a record of the shared app. `coreapp/cores/amiga.cc` makes two descriptors from one source and an override list:
  `amiga_desc = make(0)` (the A500) and `amiga1200_desc = make(1)`. The shared app's table holds both.
- The A1200 has no TOML B and no TOML A of its own. Its registers are the C defines of `coreapp/cores/amiga_regs.h` (the core window,
  page 0: `AM_CTRL` 0x0A0, `AM_MEM_CFG` 0x0A1 ... `AM_RTC_STAT` 0x0E3). Its data description is `cores/amiga1200/app/desc.toml`.
- It is a large core: `cores/amiga1200/mono/core.toml` (one flat design, its own copy of the host). The builds repository holds its
  flat bitstreams as `bit-mono-amiga1200-<key>`. The old pipeline packs it with `tools/pack_large_cor.sh` and the shared app.
- `tools/core_toml.py list-own-app` lists the DFX cores only (`descriptors()`), so the dispatcher does not see a large core. The
  bitstream lane fetches `core:<id>` entries only. Step 11 packs a partial (`ci/pack_one.sh`). The emulator flow is the VIC-20's.
- ue2emu starts a large core from the host by IPROG and the boot magic (`--icap`, `--cor-dir`, `--core-dir`; its `docs/FEATURES.md`,
  S44 phase B), so the host flow of step 12 can run with the A1200's `.cor`.

The parts:

- **P1 The app.** The A1200's code becomes its library in `cores/amiga1200/app/lib`: its own copy of `amiga.cc` (the A1200's record
  only), `amiga_regs.h`, `amiga_keys.h`. Its TOML B names that library, the shared libraries it links, and its descriptor (the switch,
  `[app] desc`). The A500 keeps the shared app.
- **P2 The TOML A.** The A1200's register blocks as `cores/amiga1200/app/gateware.toml`, and the base blocks it takes from the host's
  TOML A, checked against the RTL by `tools/rtl_check.py` (a case of `tests/rtl_check`).
- **P3 The tests.** The units of its libraries, built as its app, named per step in its TOML B (T239.5 D4).
- **P4 The large `.cor`.** Its flat bitstream and its own app (`tools/pack_large_cor.sh`: the heap from its link, record 6).
- **P5 The matrix for a large core.** The dispatcher sees it; its bitstream lane fetches its flat bitstream (or the builder builds
  it); steps 3, 4, 11, 12 and 13 take the large core's variant.
- **P6 What stays.** The shared app keeps the A500 and the A1200's record; the old pipeline is not changed (T239.5 D11).

## §2 Scenarios

Each is proven by the matrix run named in §5 (its job and step lines), or by Alex's board session.

- **S1 (P1):** the A1200's app links from the SDK package alone (`tools/sdk_core_app.sh`); `tools/libtab.py mapcheck` finds in the
  link map its library, the shared libraries its TOML B names and the base, and nothing else. Proof: step 6 of its lane.
- **S2 (P2):** `gateware.toml` and the base blocks it names agree with the RTL of the A1200's design, block by block and property by
  property. Proof: the A1200's case of `tests/rtl_check` (step 4 and the lint leg `core:amiga1200`).
- **S3 (P3):** the units its TOML B names pass, built as its app: step 2 (its own libraries), 8 (mock bitstream -> service), 9 (service
  -> UI), 10 (service -> API). Proof: steps 2, 8, 9, 10.
- **S4 (P4):** its `.cor` holds its flat bitstream and its own app; `tools/cor_pack.py check` accepts it; the image, the heap and the
  stack reserve fit the application region. Proof: steps 7 and 11.
- **S5 (P5):** a push to `t239.3` runs the A1200's lane, steps 1 to 13, and its bitstream lane by `large:amiga1200`. Proof: the run.
- **S6 (step 12):** in ue2emu the host app starts the A1200's `.cor`, the A1200's menu shows its Home, and the way back reboots the
  host. Proof: the emulator job's PASS line and its pictures.
- **S7 (P6):** the shared app still builds and its units pass with the A500's and the A1200's records. Proof: the SDK lane, step 2.
- **S8 (board):** the A1200's `.cor` from the matrix boots on the board, starts Kickstart and runs AmigaVision from HDF as in T97.
  Proof: Alex's board session.

## §5 Build notes

On the branch `t239.3`. The P1 and P2 agent's work was checked by the coordinator against the code.

**P1 (19d1dbd30).**
- `cores/amiga1200/app/lib/amiga1200.cc` is `coreapp/cores/amiga.cc` with the A1200's row only: `variants[1]`, `amiga1200_desc =
  make(0)`, no A500 tables. The stride, the FEAT masks and the KPI bits are driver-table names.
- `amiga1200_regs.h` defines the AM_* names through `drvtab.h` (offset = address minus `DRV_ident_ADDR`). Check: the header compiled
  against the driver table that `tools/sdk_core_app.sh --no-link` (SDK 0.4.7) generates from `gateware.toml`. All 59 names of the old
  `amiga_regs.h` have the same values.
- TOML B, `base_blocks`: cart_regs, the four ICAP blocks, partition, audio_master. Partition stays because the shared app links it for
  the A1200 today. A flat core has nothing to decouple.
- TOML B, libraries: amiga1200, newdisk, newfile, pad, mouse, folderhd, fastseek, ftp. Each has the sources and headers of
  `coreapp/libs/shared.toml` (S12). Not linked: sid, tempdisk, t64, c64cart, cbm1541, cbmrun, cbmprg, dma, resample, padkeys. The
  A1200's code calls none of them. Generic code finds sid and tempdisk by name only (`SvcLib::find`), as in the VIC-20's app.

**P2 (c63300c27).**
- `gateware.toml`: 17 blocks, 54 properties. Base: ident, irq, ddr_cal. Core: machine, video, stat, diw, crop, rtc, floppy, hdf,
  mbox, mouse, rawkey, pad2, dlog, pixel.
- The rtl_check case reads its own source list, `cores/amiga1200/app/rtl_check_sources.tcl`. Reason: `tools/rtl_check.py` reads the
  file names of a list as text. It does not apply the `ni` filter of `cores/amiga1200/core_sources.tcl`. With that list it checked the
  A500's `cores/amiga/rtl/trx/amiga_regs.v` (6 findings: diw, crop). Cost: a change to the register path in `core_sources.tcl` must
  also be made in the list.
- Local result: `PASS: amiga1200: 17 blocks, 54 properties of gateware.toml agree with the RTL of the core window`.

**P4, P5 (6a10c9c1b, d61a58d91, 676abc756, bc8eb12af).**
- `tools/core_toml.py lanes` lists the core lanes with their kind (dfx, large). `list-own-app` stays DFX-only, so the old pipeline
  does not see the A1200's TOML B (P6).
- The dispatcher gives the A1200 the target `large:amiga1200` (work order, bitstream lane).
- `ci/lane.sh`, step 3: the files of its flat key (`ci/lib.sh mono_specs`, which `mono_key` uses). Step 11: `tools/pack_large_cor.sh
  --sizes <TOML B> --heap 0` with the restored entry `mono-amiga1200-<key>`. Bitstream lane: fetch and report of `mono-<id>`.
