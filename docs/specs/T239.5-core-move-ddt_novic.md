### Core move: ddt_novic (2026-11-25)

Moved with `tools/core_move.py` and the core-move skill (T239.5 D16, lane B, first core). Branch `t239.5-cores-b`.

- **Commits by phase.** `449592382` library, TOML A, TOML B, desc.toml, removal from the shared app (`table.cc`, `cores.h`, the board Makefile, D24 ledger and targets,
  `check_core_id.py`, `release_notes_mc.py`, `core.toml`, `docs/dev/core-app-guide.md` section 9); `bf2ddb258` tests (`ddtapp` units, shared builds without the core, keywalk goldens, rtl_check case).
- **TOML A numbers.** The emitter's first form (full 64 KiB scan): 6 blocks, 20 registers, 10 unnamed. By hand: 6 blocks (`ident`, `irq`, `ddr_cal`, `geom`, `machine`, `video`), 19 properties,
  all named, no `# TODO` left; `rtl_check check`: "6 block(s), 19 properties agree". Page 6 (0x101A6000, the host's pixel layer, a run of 1024 words in the emitted file) is not described: the core's
  code does not use it and the host's TOML A owns that layer. `geom.lines` is 8 bit: `ddt_regs` answers GEOM_LINES as 16 bit at 035-036, but with 200 lines byte 036 is constant 0, which the checker
  sees as no read.
- **Registers by number.** `ddt_regs.h` names every register through `drvtab.h` (`DDT_OFS(DRV_<block>_<prop>_ADDR)`, masks `DRV_machine_*_MASK`, reset values `DRV_video_fb_*_reset`); the old numbers
  (0x0A0, 0x0A4, 0x0C0, 0x0C1, 0x0C4, 0x0C8, 0x01D00000, 0x00100000) are proved by `test_ddt` against `ddt_regs.v` (regexes on the decode) and `lint-src` (no literal I/O address in 2 files).
- **SDK gaps.** None found by the dry run (6 blocks, 20 registers, `rtl_check` agrees, no compile errors). `core_move.py sdkgaps` reports 2 breaks (`cart_regs`, and all blocks together:
  `hw.cc:90 DRV_cart_regs_ADDR`); identical on the unchanged `t239.3` tip, so not caused by this move: `cart_regs` is a block every app has.
- **Shared files copied.** None (the plan listed none: the closure of `ddt_novic.cc` is `ddt_novic.cc` and `ddt_regs.h`).
