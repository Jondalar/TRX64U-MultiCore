### Core move: cpc (2026-11-25)

Moved with `tools/core_move.py` and the core-move skill (T239.5 D16, lane B, third core). Branch `t239.5-cores-b`. The Amstrad CPC is a large core (`cores/cpc/mono/core.toml`, `pipeline = false`: no pipeline stage builds its gateware, packs it or benches it; lint, the app and its unit tests still read it, T92 D-17e).

- **Commits by phase.** `4f21814f6` library (`cpc.cc`, `cpc_disk.*`, `cpc_regs.h` moved; copies of `hk_defaults.h`, `tape_deck.*`, `tape_pulses.*`), TOML A, TOML B, `desc.toml` by name, removal from the shared app (`table.cc`, `cores.h`, the board
  Makefile, D24 ledger and targets, `check_core_id.py`, `release_notes_mc.py`, `cores/cpc/mono/core.toml`, `coreapp/README.md`, the comment in `tb_cpc.v`); the tests commit (the `cpcapp` units, shared builds without the core, keywalk goldens, rtl_check case,
  `check_no_rom.py`, TOML B `tests`) follows it; this note is its own commit.
- **TOML A numbers.** The emitter's first form (full 64 KiB scan, about 20 minutes on this Mac): 13 blocks, 45 properties, 16 of them unnamed. By hand: 12 blocks (`ident`, `irq`, `ddr_cal`, `geom`, `machine`, `video`, `win`, `tape`, `inject`, `disk`, `dirty0`,
  `dirty1`), 41 properties, all named, no `# TODO` left; `rtl_check check`: "12 block(s), 41 properties agree". The emitter's byte runs became counted properties (`inject.keys` 10 bytes, `dirty0.map` and `dirty1.map` 8 bytes each; the app writes and reads them byte by
  byte as `CPC_D0_DIRTY + m`). `geom.frame_clks`, `src_w`, `src_h` are 16 bit at 031, 034, 036 (the RTL reads those bytes; 030 and 033 are constant 0), `bufs` 8 bit at 038. `tape.status` and `tape.underrun` are two 8 bit properties (the emitter had one 16 bit
  read). Page 6 (0x101A6000, the host's pixel layer) is not described: the core's code does not use it and the host's TOML A owns that layer. `[identity] id = "CPC_"`.
- **rtl_check source list.** `core_toml.py sources cpc` names the whole `cores/cpc` tree including `mono/host` (the flat build's copy of the host) and the Spectrum core's AY, Z80 and shared parts under `cores/zx`; `cores/cpc/app/rtl_check_sources.tcl` is the emitted list and the check
  agrees with it, as it is.
- **Registers by number.** `cpc_regs.h` names every register through `drvtab.h` (`CPC_OFS(DRV_<block>_<prop>_ADDR)`, masks `DRV_*_MASK`); `desc.toml` names its registers as `"block.property"` (`video.fb_latest`, `video.frame_seq`, `video.fb_base`, `video.fb_stride`,
  `machine.status`) and the two reset values as `video.fb_base.reset`, `video.fb_stride.reset`. `rtl_check.py lint-src` over `cpc.cc`, `cpc_regs.h`, `cpc_disk.cc`, `cpc_disk.h`: "no literal I/O address in 4 file(s)". A throwaway program (not committed) built `cpc_regs.h` against the driver table made from `gateware.toml` and compared the 25 offsets with the numbers of the old header (`git show HEAD~1:coreapp/cores/cpc_regs.h`): "compared 25 registers, 0 differ".
- **SDK gaps.** None found by the dry run (12 blocks, 44 registers, `rtl_check` agrees, no compile errors). `core_move.py sdkgaps` reports the same 2 breaks as for ddt_novic and zx (`cart_regs`, and all blocks together: `hw.cc:90 DRV_cart_regs_ADDR`), a block every
  app has, not caused by this move. One harness gap, fixed once for every core: the control job of `tests/coreapp/run.sh` copied only the shared sources into its mutation folder, so a negative control on a file of an app's own library (`cpc_disk.cc`) found nothing to
  break; it now copies `$APPLIB` over the shared sources of the same name (an app without `APPLIB` is unchanged).
- **Shared files copied (copy rule).** `hk_defaults.h` (6696d1028), `tape_deck.cc` (2fd95fc63), `tape_deck.h` (650507adb), `tape_pulses.cc`, `tape_pulses.h` (2fd95fc63) into `cores/cpc/app/lib`, each with a first line naming its source path and commit; the originals stay in

  libraries `newfile` and `newdisk` (Create blank DSK). The test harness builds the app's own copies: `cpcapp` sets `APPLIB`, which `find_src` tries first.
