# T25.3 — Clean-room audio decimator (lp_filter / resampler replacement)

**Status:** spec 2026-10-02; built on branch `t25-sid` (`cores/trx_sid/rtl/trx_audio.v`), simulated, not yet on the board. Decisions and results: §3.5. **Task:** TODO.md T25 (overview:
`docs/specs/T25-cleanroom-multisid.md`). **Input from:** T25.1 (`T25.1-sid-engine.md`, one
sample per SID per C64 cycle), drive sound, later tape/sampler. **Output to:** I2S codec and
speaker (`i2s_out.v`), HDMI audio, UDP audio stream (`udp_audio.v`).

**One sentence:** mix all sources at the C64 cycle rate with the app's per-source gains and
pans, then low-pass and decimate the stereo sum from 985 kHz to the 48 kHz I2S frame with a
CIC + polyphase FIR whose phase follows a fixed, exact ratio, because the C64 clock and the
audio MCLK come from the same 50 MHz crystal.

**Clean-room rule.** Written without opening Gideon's `fpga/io/audio/lp_filter.vhd`,
`lp_filter2.vhd` or `sys_to_aud.vhd`, and without his closed U64 mixer/resampler (never in the
repo). Sources: the app's code (what it writes), Gideon's public stream documentation, DSP
textbooks/articles and open filter cores listed in §6.

All app citations are `path:line` in `software/ultimate-app` at submodule commit `25568658`.

---

## 1. What the block does for the app and the user

### 1.1 Mixer (write-only registers, `software/system/u64.h:16-17`)

- `U64_AUDIO_MIXER` (0x10100500), 20 bytes: per source a **right** then a **left** gain
  (`setMixer`, `software/u64/u64_config.cc:1369-1391`: `*(mixer++) = vol_right; *(mixer++) =
  vol_left`). Sources in order (`u64_config.cc:441-462`): 0 UltiSID 1, 1 UltiSID 2, 2 Socket
  1, 3 Socket 2, 4 Sampler L, 5 Sampler R, 6 Drive 1, 7 Drive 2, 8 Tape Read, 9 Tape Write.
- Gain: 0x80 = 0 dB (`volume_ctrl[24]`, `u64_config.cc:305-308`), 0xFF ≈ +6 dB, 0 = off;
  master folded in by `combine_mixer_gain` (`:310-320`); pan law `pan_ctrl` 0..256 over 11
  steps (`:322`), applied as `(pan * vol) >> 8`.
- `U64_SPEAKER_MIXER` (0x10100540), 20 bytes, same layout, both bytes of a source equal
  (`setSpeakerMixer`, `:1410-1430`); all zero when the speaker is off.
- Registers read back as zero (comment and code at `u64_config.cc:1362-1367`: the app restores
  from its settings, never reads).
- The freezer zeroes bytes 0-7 of both mixers around its `$D418` writes and restores them
  afterwards (`u64_mute_sids`/`u64_unmute_sids`, `:1345-1367`). The SID player autoconfig
  rewrites bytes 0-7 per tune (`SetMixerAutoSid`, `:2013-2057`).

### 1.2 Resampler (write-only, `u64.h:18, 82-85`)

`SetResampleFilter` (`u64_config.cc:2242-2257`), called whenever the video PLLs are set
(`:1168` for U64-II/C64U, `:1179` for U64):

| Register | Write |
|---|---|
| `U64_RESAMPLE_RESET` (+0x04) | 1 |
| `U64_RESAMPLE_FLUSH` (+0x09) | 1, then 0 at the end |
| `U64_RESAMPLE_DATA` (+0x00, 32 bit) | the coefficient table, one word per write: PAL 675 words (`c_filter2_coef_pal_alt`, `:2148`), NTSC 512 words (`c_filter2_coef_ntsc`, `:2208`) |
| `U64_RESAMPLE_LABOR` (+0x08) | 45 (PAL) or 169 (NTSC) |

675 = 15 x 45 and 507-512 ≈ 3 x 169: a polyphase FIR with 15 (PAL) or 3 (NTSC) phases and
LABOR taps per phase. Gideon's public stream documentation gives the output rates as
`Fc*16/9*15/77/32` = 47,983 Hz (PAL) and `Fc*16/7*15/80/32` = 47,940 Hz (NTSC)
(GideonZ/1541u-documentation `data_streams.rst`), i.e. the audio clock is locked to the
colour clock and with it to the C64 clock: audio/C64 = 15/308 (PAL) and 3/64 (NTSC). That
fits the 15 and 3 phases. What sits in front of the resampler (the closed `lp_filter`) is not
visible from the app; the rates suggest a first decimation stage. We do not need to know.

### 1.3 Streams and outputs

- The audio stream (ID 1) is "taken from the output of the audio mixer", 192 stereo 16-bit
  samples per packet (`data_streams.rst`). Ours sends the top 16 bits of the same 24-bit
  samples at 48.003 kHz (`designs/c64_basic/udp_audio.v`, instance `top.v:859-860`).
- HDMI audio at `AUDIO_RATE(48_000)` from the same samples (`top.v:1138-1149`), I2S to the
  codec and the speaker (`top.v:1155-1158`).

## 3. Required behaviour

### 3.1 Signal chain

```
per SID (T25.1), drive, tape, sampler   @ f_phi2 (985,243 Hz PAL, C64 clock domain, ce = C64 cycle)
  -> mixer: per source gain L/R (main) and mono (speaker), 10 sources, saturating sum, 2+1 channels
  -> stage 1: CIC decimator /4, order 6  (-> 246,311 Hz)
  -> stage 2: polyphase FIR, fractional ratio 4 x 2400/49259, phase from a fixed accumulator
  -> DC blocker (keep today's, now after the filter)
  -> CDC to mclk (one sample per I2S frame, FIFO depth 4)
  -> I2S / HDMI / UDP (unchanged)
```

- **Mixer** in the C64 clock domain with the app's 8-bit gains (0x80 = 0 dB, saturate at
  ±2^23): main mixer per source R/L bytes as the app writes them; speaker mixer mono. Bytes
  0-7 are the SID sources (UltiSID 1/2 sums from T25.1; sockets: none fitted on the C64U, keep
  the inputs at 0). Gain changes take effect at the next sample (the app writes them while
  sound plays; a 1-sample step is inaudible at 985 kHz after the filter).
- **Stage 1 CIC** (R = 4, N = 6, M = 1): N = 6 is the lowest order that keeps the bands that
  fold into 0-28 kHz (218-274 kHz and up) at ≤ -104 dB; N = 4 gives only -69 dB, N = 5 -87 dB
  (computed 2026-10-02). Droop -0.53 dB at 20 kHz, corrected in stage 2's prototype. The three
  channels share one adder, time-multiplexed, with the 12 x 3 accumulators (36 bit) in LUTRAM:
  36 additions per C64 cycle against 64 engine clocks.
- **Stage 2 fractional polyphase FIR:** prototype low-pass designed at 64 phases x T taps,
  pass band 0-20 kHz, ripple ≤ 0.1 dB including CIC compensation, stop band from 28 kHz
  (everything above 28 kHz folds to above 20 kHz at 48 kHz, inaudible) with ≥ 90 dB. One
  output per I2S frame: the phase accumulator advances by `4 * 2400/49259` input samples per
  output (exact rational, 32-bit fractional accumulator with the remainder carried, so no
  drift and no servo); linear interpolation between adjacent phases. T ≈ 24-32 taps per phase
  at 246 kHz (to be confirmed by the design script).
- **Board output stage** of the real C64 (reSID `extfilt`: ~16 kHz 1-pole LP): folded into the
  prototype as an optional response, selectable (Q4).
- **DC blocker** after stage 2 (corner ~2-7 Hz), so `$D418` digis survive as audio but the
  static DC offset does not reach the codec.
- **Pause:** the C64 clock stops, so input samples stop. Output then ramps to 0 over ~5 ms
  (no click) and resumes from the filter state when the machine runs again. Replaces today's
  hard mute in `top.v`.
- **Resampler registers** (0x10100580-89): accept and ignore (writes acknowledged, reads 0).
  Our rates differ from the U64's (48,003 vs 47,983 Hz), so the app's 15/3-phase tables do
  not fit our ratio; we use our own fixed coefficients (Q1).

### 3.2 Alternative A (not proposed): lock MCLK to the C64 clock

Derive MCLK from dot4x so that fs = f_phi2 x 15/308 (47,982.6 Hz with our 985,243 Hz), as on
the U64; then stage 2 becomes a plain 15-phase polyphase like the app's table, and our stream
rate equals the U64's. Costs a clock resource (MMCM/PLL; `top.v:145-147` already shares one
MMCM between MIG, MCLK and the CPU) and puts C64-clock jitter on the codec. The fixed-ratio
design above gets the same quality without it.

### 3.3 Accuracy targets

| Item | Target | Check |
|---|---|---|
| Pass band 20 Hz-20 kHz | ±0.1 dB (incl. CIC droop) | design script + Verilator impulse/sine sweep |
| Aliases into 0-20 kHz | ≤ -90 dBFS for a full-scale tone anywhere 28 kHz-492 kHz | sine sweep sim, FFT of output |
| Ratio | no drift: 48,003.07 output samples per 985,243.06 input samples, long-run exact | counter check over 10^9 cycles in sim |
| Noise floor | ≤ -100 dBFS (24-bit path, ≥ 18-bit coefficients) | sim with silence + dither off |
| Latency | ≤ 1 ms | sim |
| Listening | no audible aliasing on pulse/saw sweeps (e.g. high-pitched SID leads) vs today's build | A/B on the board |

### 3.4 Open questions

1. Ignore the app's resampler table (proposal) or implement Alternative A to be rate-identical
   with the U64 stream (47,983 Hz) for tools that assume it?
2. Mixer at the C64 rate (one MAC per source per cycle, 10 sources x 3 channels = 30 MACs per
   C64 cycle, fine on one DSP at 2 x dot4x) or per-source decimation? Proposal: mix first, one
   filter for the stereo sum, one for the speaker.
3. Drive sound (`drive_audio` 13 bit) and tape sounds: their own clock domain; feed them as
   held values sampled at the C64 rate (their content is low-frequency clicks).
4. Should the C64 board's ~16 kHz RC low-pass be emulated (authentic dull top end) or left
   out (U64 behaviour unknown; measure the U64 stream's response with a SID noise test)?
5. HDMI: the ACR N/CTS in `hdmi` already describe 48 kHz against the pixel clock; with 48,003
   Hz the sink sees +64 ppm. Fine for all sinks tested so far? (existing behaviour, not new)

### 3.5 Decisions and results (as built, 2026-10-02)

| # | Item | Decision |
|---|---|---|
| E1 | Chain | Changed from one 64-phase FIR at 246 kHz: that prototype needs ~176 taps per phase for 90 dB with a 20-28 kHz transition, ~5 BRAM tiles of coefficients. Built: CIC /4 (N = 6, 36-bit state in LUTRAM, one adder) -> 15-tap halfband /2 (123 kHz) -> 35-tap halfband /2 (61.6 kHz) -> fractional FIR 56 taps x 32 phases, phases linearly interpolated (Kaiser, cut-off 23 kHz, CIC and halfband droop compensated), coefficients 896 x 18 bit in one RAMB18 (symmetric half). Each stage guards only the bands folding into 0-28 kHz (0-20 kHz at the last); the next removes the rest. Design script `cores/trx_sid/model/design_decim.py` (SciPy) writes `cores/trx_sid/mem/decim_*.mem`. |
| E2 | Ratio | The output position advances by 49259/38400 input samples per output in an integer accumulator (exact, no drift); the interpolation fraction is `rem x 55924 >> 14` (1/4096 of a phase). |
| E3 | Q1 resampler registers | Not decoded (as today): the app's table is for its 47,983 Hz, ours runs at 48,003.07 Hz. |
| E4 | Q2 mixer | Mix first at the C64 rate: UltiSID 1 and 2 (the four per-UltiSID sums of T25.1) with the app's bytes 0-3 of `U64_AUDIO_MIXER` (R, L per source, 0x80 = 0 dB); `top.v` no longer applies its `mix_l/mix_r` gain. Sockets, drive, tape: no inputs yet (0). **T25.6: the sampler L / R are inputs 2 / 3 now (bytes 8..11 of the app's mixer), the four products per side run through one multiplier (bit exact with the old mixer when the sampler is silent, 13 DSP instead of 16 in trx_audio).** The speaker still takes the main mix with its own gain (`mix_spk`), so it also carries the main gains: a separate speaker mix is left for later. |
| E5 | Q3 drive/tape | Not connected yet. |
| E6 | Q4 C64 RC low pass | Not emulated. |
| E7 | Pause | The output FIFO (8 entries, refilled to 3 before it plays) runs dry when no C64 cycles come; the output then decays with a time constant of 64 frames (1.3 ms, < 3 % after 5 ms) and resumes from the filter state. `top.v`'s cut on the app's C64_STOP stays. |
| E8 | DC blocker | After the FIFO in the MCLK domain, `y = x - x1 + y1 - y1/4096` (corner ~1.9 Hz, -0.04 dB at 20 Hz; the old 1/1024 gave -0.55 dB at 20 Hz). |

Results (`designs/c64_basic/sim/sid/analyse_audio.py` on the Verilator bench with both real
clocks): pass band 20 Hz-20 kHz within -0.043/+0.035 dB (0.078 dB peak to peak); worst alias
into 20 Hz-20 kHz for full-scale tones from 28 to 490 kHz: -108 dBFS; FIFO level constant (3)
while running, so production and consumption rates match. Resources
(yosys, `trx_audio` alone): ~1,175 logic LUT + 65 LUTRAM primitives (~260 LUT), 1 RAMB18,
12 DSP — more LUT than §4 estimated (saturation, 36-bit CIC path, two halfbands).

## 4. Resource estimate and fit

| Part | LUT | FF | BRAM tiles | DSP |
|---|---|---|---|---|
| Mixer: 10 sources x 3 gains in LUTRAM, MAC sequencer | 120 | 100 | 0 | 1 |
| CIC /4, N = 6, 3 channels time-multiplexed (one 36-bit adder, state in LUTRAM) | 150 | 120 | 0 | 0 |
| Polyphase FIR: coefficient ROM 64 x 32 x 18 bit, delay lines 3 x 32 x 24 bit (LUTRAM), phase accumulator, interpolation, MAC sequencer | 250 | 250 | 0.5 | 1 |
| DC blocker (keep `dc_blocker.v`, 3 channels) | 270 | 130 | 0 | 0 |
| CDC FIFO to mclk | 40 | 60 | 0 | 0 |
| **Total** | **~830** | **~660** | **0.5** | **2** |
| Removed: reDIP's per-SID CDC + 2 DC blockers before the decimation, `top.v` gain logic | -230 | | | |

Net ≈ +600 LUT, +0.5 BRAM tile, +2 DSP. With T25.1 (±0..+300 LUT, -3.5 tiles) the audio work
lands at ~24.3-24.6k LUT (75 %) and ~53.5 BRAM tiles (71 %): inside the 80 % ceilings. The
DC blockers can share one time-multiplexed IIR (saves ~180 LUT) if LUTs get tight.
