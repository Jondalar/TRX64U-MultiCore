### Core move: pet (2026-11-25)

Moved with `tools/core_move.py` and the core-move skill (T239.5 D16, lane B, fourth core). Branch `t239.5-cores-b`. The Commodore PET is a large core (`cores/pet/mono/core.toml`, delivery `cfw`, experimental).

- **Commits by phase.** `2f677f93a` SDK gap (`descrec.py`, `api.md`: a `[pad] regs` list is named as `block.property`); `9d049beb2` SDK gap (`tests/coreapp/srclist.sh`: the same code of two cores' copies once); `46a543ee1` library (`pet.cc`, `pet_models.h`, `pet_regs.h`, `tape_deck.*`, `tape_pulses.*` moved, copy of `hk_defaults.h`), TOML A, TOML B, `desc.toml` by name, removal from the shared app (`table.cc`, `cores.h`, the board Makefile, D24 ledger and targets, `tests/coreapp/cores.txt`, `check_core_id.py`, `release_notes_mc.py`, `cores/pet/mono/core.toml`, `coreapp/README.md`); `481f0f14a` tests (the `petapp` units, shared builds without the core, keywalk goldens, rtl_check case); this note is its own commit.
- **TOML A numbers.** The emitter's first form (full 64 KiB scan, about 25 minutes on this Mac): 9 blocks, 51 registers, 14 of them unnamed (`# TODO`), a 1024-element read run for page 6. By hand: 10 blocks (`ident`, `irq`, `ddr_cal`, `machine`, `rom`, `video`, `drive`, `dlog`, `tape`, `pads`), 55 properties, all named, no `# TODO` left; `rtl_check check`: "10 block(s), 55 properties agree". The emitter's 32-bit run `padkey0` + byte `r_168` became five 8-bit properties `padkey0` to `padkey4` (the app writes them byte by byte, `PET_PADKEY0 + i`); `size0`/`size1`, `base0`/`base1` are separate 32-bit properties (the app takes `PET_DRV_SIZE0 + 4 * d`); `machine.frames` (0A8) and `machine.cpuaddr` (0AC) are 16 bit, `video.fb_overruns` (0C2) 16 bit, `tape.status` (150) and `tape.underrun` (151) two 8-bit properties, the `dlog` block (0F0 to 0F3) is the drives' write log. Page 6 (0x101A6000, the host's pixel layer) is not described: the core's code does not use it and the host's TOML A owns that layer. `[identity] id = "PET1"` (the emitter guessed `PET_`; the RTL answers `PET1`, byte 0 first). The 16 KB ROM aperture is a DMA window of the host, `rom.rom_sel` only selects what is behind it.
- **rtl_check source list.** The core has no `core_sources.tcl`; `core_toml.py sources pet` names the whole `cores/pet` tree including `mono/host` (the flat build's copy of the host); `cores/pet/app/rtl_check_sources.tcl` is the emitted list and the check agrees with it as it is.
- **Registers by number.** `pet_regs.h` names every register through `drvtab.h` (`PET_OFS(DRV_<block>_<prop>_ADDR)`, `PET_ST_HELD` = `DRV_machine_status_held_MASK`); `desc.toml` names its registers as `"block.property"` (`video.fb_latest`, `machine.model`, `tape.pin`, `pads.padkey0` to `pads.padkey4`, `pads.pad1`, `pads.pad2` ...) and the reset values as `video.fb_base.reset`, `video.fb_stride.reset`. The compiled record is byte for byte the old one (8305 bytes, compared with the description of `46a543ee1~1`). `rtl_check.py lint-src` over `pet.cc`, `pet_regs.h`, `pet_models.h`, `tape_deck.*`: "no literal I/O address in 5 file(s)". A throwaway program (not committed) built `pet_regs.h` against the driver table made from `gateware.toml` and compared with the numbers of the old header (`git show 46a543ee1~1:coreapp/cores/pet_regs.h`): "compared 35 registers, 0 differ". `test_hotkeys.cc` keeps the register numbers 0x164 to 0x168 literally as the expected values (the T232 case), which is the same check the other way.
- **SDK gaps.** (1) The dry run found none (9 blocks, 51 registers, `rtl_check` agrees, no compile errors). (2) `[pad] regs = ["pads.pad1", "pads.pad2"]` was refused (the A1200's, the NES's, the SNES's and the Neo Geo's descriptions still write the two numbers): `descrec.py` now resolves the strings of a `regs` list (a number stays a number), `api.md` 6.14.20 says so; the record is unchanged. (3) `tools/menusim/run.sh` and the render bench (`tests/coreapp/srclist.sh`) compile every own app's library into one native program; the Spectrum's and the CPC's copies of `tape_deck.cc` and `tape_pulses.cc` already defined the same functions twice, with the PET's a third time ("ld: 11 duplicate symbols"): the list now takes a file once when another own core already has the same code but for the leading "Copy of" line. `tools/menusim/run.sh pet --keys F5 --shot` links and renders the PET's F5 page (Model, CPU speed, Diag jumper, RAM, Drive, Datasette port). `core_move.py sdkgaps` reports the same 2 breaks as for the cores before (`cart_regs`, and all blocks together: `hw.cc:90 DRV_cart_regs_ADDR`), a block every app has, not caused by this move.
- **Shared files (copy rule).** `hk_defaults.h` (6696d1028) is copied into `cores/pet/app/lib` with a first line naming its source and commit; the original stays for the cores that have not moved. `tape_deck.*` and `tape_pulses.*` were the shared app's last copies (the Spectrum's and the CPC's apps have their own since their moves), so they moved with `git mv`, the originals are gone from `coreapp/cores`; no core that stays names them (`grep` over `coreapp`, `uicore`, `tools`, `ci`, `tests` finds only the three apps' libraries and the units). The comment of `tape_deck.h` that spoke of the Spectrum and the CPC was corrected. The two controls `mme_tape_notify` and `mme_tape_fail` (a mutation of `tape_deck.cc`) had no case left in the shared `media_mounts_engines` (the tape case of the CPC and the Spectrum run in their apps) and would have lost their source: they run as `cpcapp control ... $CPCM` now, where the tape case is, and both fail as they must.
- **Units, old name -> new name.** `pet_models` keeps its name (now built as the app: `petapp`, the group `pet`); the tape converter's test runs as `tape_pet` (the unit `tape` of the shared app is gone: the PET was its last user). The PET's cases of the shared `desc` (golden `menu_pet.txt`, the machine line, the T206 walk of the drive images, the write-back hand-over of `PET1`, the tape keys of T212 D10), `descgen`, `hotkeys` (S5 row and T232: the pad keys A-Z and learn by key press) and `cut` (T228 DC5, the machine line names the RAM only while its row is shown; it needed `SioModel` and the NES record only by habit: it is the file `test_pet_cut.cc`, built on the fake I/O) and `gen_romreq` (the PET's rows against `romreq_table.inc`) -> `pet_desc`, `pet_descgen`, `pet_hotkeys`, `pet_cut`, `pet_romreq`. TOML B `tests = { unit = ["pet_models", "tape_pet"], service = ["pet_descgen", "pet_romreq"], ui = ["pet_desc", "pet_hotkeys", "pet_cut"] }`; there is no case of step 10 (service -> API): the PET has no memory window of the application's, no `read_mem`, and the shared `memops` never had a PET row. The shared test files carry `TEST_APP_PET` branches; the shared `n205` count is 12 now. The `pet_desc` unit asserts one more than the shared one did: `PET1` hands its write-back over (`media_flush`, `media_pending`). No negative control was moved or added (the PET's engine had none).
