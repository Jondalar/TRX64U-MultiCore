## §1 The problem

- **Who:** the maintainer, outside contributors, and every CI stage.
- **What they try to do:** develop in the open on GitHub. A contributor forks, changes, opens a pull request, and sees a CI result. The maintainer merges it without a second copy of the history.
- **What happens today:**
  - Gitea (the internal server, organisation TREX) is `origin`. The GitHub repository `Jondalar/TRX64U-MultiCore` is public, its default branch is `main`, and it has 8 collaborators, all with push permission (`gh api repos/Jondalar/TRX64U-MultiCore/collaborators`, read 2026-11-19). It has no `.github/workflows/`; only `.github/ISSUE_TEMPLATE/` exists in the tree.
  - GitHub main is a filtered replay of the Gitea history: `tools/github_snapshot.py` (390 lines) rewrites every commit and `release/github_map.txt` (946 lines) maps Gitea shas to GitHub shas. The two histories have different shas.
  - Outside pull requests are applied as patches on Gitea (T239 §1).
  - CI is 11 workflow files in `.gitea/workflows/` (`apptests`, `cor`, `emu`, `images`, `nightly`, `package`, `pipeline`, `sim`, `sims-long`, `update`, `vivado`). The parent `pipeline.yml` runs on the pool `nas` and dispatches the children through the Gitea API (`ci/orchestrate.py:155,172`: `/api/v1/repos/.../actions/workflows/<wf>/dispatches?return_run_details=true`), with `ORCH_TOKEN` from `secrets.PACKAGE_TOKEN` and `ORCH_TOKEN2` from `secrets.GITEA_TOKEN || secrets.GITHUB_TOKEN` (`pipeline.yml:64-93`). `ci/orchestrate.py check` requires the parent to run on `nas` (`:459`). Children run on `${{ vars.CI_RUNNER || 'builder' }}` and mount the builder's cache volume as `/cache`.
  - The builder and `/cache` are shared with TREX/TRX64-Ultimate. `/cache/heavy.lock` is the one shared Vivado lock (`ci/lib.sh:325-372`); the content-keyed cache and hand-over directories live in `/cache/multicore` (`ci/lib.sh:16-17`).
  - Packages go to the Gitea generic package registry: `ci/lib.sh:314` (`PUT .../api/packages/<owner>/generic/<pkg>/<version>/<file>`, `PACKAGE_TOKEN`), `ci/package.sh:139`, `ci/update.sh:30`, `tools/pack_import_cor.sh:60`, `tools/pack_cores_mc.sh:59`, `tools/release_mc.sh:61`, `tools/load.sh:11,21`. `ci/child.sh:36,80` writes commit statuses and reads run state through the Gitea API.
  - Private material in the tree, found by `git ls-files`:
    - ROM images: `roms/1541-ii.bin`, `roms/basic.901226-01.bin`, `roms/characters.901225-01.bin`, `roms/kernal.901227-03.bin`; `cores/atari800/roms/{ataribas,atarixl,pbi_bios}.rom` (the XL OS and BASIC, T-rule of 2026-10-14).
    - Bench media: 12 files under `cores/{apple2,c128,pet}/sim/media/` (1.6 MB with the ROMs). `cores/c128/sim/media/128-robots.d81` is also untracked in the working tree.
    - Session material: `.claude/` (16 tracked files, about 1.4 MB; the 149 MB on disk are untracked agent worktrees), `CLAUDE.md`, the contact list folder under `docs/`, the T120 licence inventory spec (and its `done/` copy), `docs/todo/T120.md`, `release/github_map.txt`, `release/imports/trx64u_files/modplayer/module.bin`, `tools/github_snapshot.py`.
    - The SPC700 boot ROM of the SNES core is not a file. The only SNES files that match a ROM extension are none (`git ls-files cores/snes` lists no `.bin/.rom/.hex/.mif`); where the 64 bytes sit in the HDL source is not located yet (open question 5).
  - What the export filter does today (`tools/github_snapshot.py`): `DROP_DIRS` (`.claude/`, the contact list folder), `DROP_FILES` (above), `DROP_RE` (`roms/*.bin`, `cores/*/roms/*.rom`, `cores/*/sim/media/*`), `ROM_EXT` (a ROM or disk extension anywhere else stops the export), `ADD` (a README in `roms/` and `cores/atari800/roms/`, from `tools/github_snapshot/`), `PATTERNS` (internal hosts, paths, internal page links, Claude trailers), `NAMES` (tester names), `EDITS` (two sentences rewritten), `FORBIDDEN` (a check on every exported blob, path and message), the T120 row of `TODO.md` removed.
  - Rules that name Gitea: `CLAUDE.md` ("Git and CI": Gitea `TREX/TRX64U-MultiCore`, only the coordinating session pushes, the Gitea token and `tea`, "Clean up right after a merge ... in Gitea", "Releases are made by hand, on GitHub", the review-before-push rule); `.claude/context.md`; `docs/board-tooling.md`; `docs/layering-map.md`; `docs/architecture-reset-2026-10-05.md`.
- **Why it matters:**
  - A public repository on a self-hosted runner runs a fork's code on the builder, next to the Vivado cache and the board tooling. Without an approval gate and without secrets for fork runs, that is remote code execution on our machine.
  - If the private files stay in the tree they become public the moment GitHub is the primary repository. ROM images and disk images are third party content (CLAUDE.md, "Clean room and licences").
  - Without a single history, no contributor commit keeps its sha, and the replay filter stays in the path of every push.

**Parts (MECE):**

- **P1** Private material leaves the tree and goes to a Gitea side repository; benches and CI fetch it from there.
- **P2** The pipeline runs as GitHub Actions on the builder as a self-hosted runner: workflow syntax, dispatch, tokens, labels, cache and lock, statuses.
- **P3** CI packages and the 0.2.0 release flow work from GitHub.
- **P4** Pull requests from forks and the protection of `main`.
- **P5** History: which repository is `origin`, what happens to the replay tool and its map, how the Gitea-only history is kept.
- **P6** The rules and docs that name Gitea are changed.

## §3 Decision

By reference to the epic, plus the decisions taken for this child (T239.1 Dn).

- **T239 D11:** GitHub is the development home; pull requests and CI there; GitHub Actions uses our builder as a self-hosted runner; Vivado stays on our machine; Gitea keeps only private material as a side repository (ROMs, bench media, session material); the history replay and its filters go away. Price named by Alex: "ROMs and bench media leave the tree."
- **T239 D13:** this is step A; after it nothing has to go through the export.
- **T239 D12:** the experimental cores stay in this tree, so their benches and their media stay part of S2.
- **T100 D8:** releases are made by hand on GitHub; CI never publishes a release. This child changes where the release is built from, not who makes it.
- **T192 D24 / T213 D4:** the move touches CI and tools only. No file in `coreapp/` or `uicore/` is touched; `tools/check_d24.py` and `tools/d24_ledger.txt` stay as they are.
- **T239.1 D1 (Alex, 2026-11-19): every build of `main` becomes a pre-release in a repository of its own (for example
  `trx64mc-builds`), on two conditions: `main` gets branch protection, and the builder's runner does not run for whatever anybody
  triggers.** Asked between workflow artifacts with hand-picked pre-releases, automatic pre-releases in an own repository, and
  Gitea packages for CI. Alex (translated): "If we introduce branch protection and my local runner does not run all the time
  because anybody triggers the CI, then 2 is ok for me. The bitstreams should become stable fairly quickly anyway."
- **Question 5, answered from the records:** the 64 bytes are the table `spc_ipl` in `coreapp/cores/snes.cc:99`; the app writes
  them into a small RAM of the S-SMP, the HDL constant was cut (`cores/snes/rtl/NOTICE`). T142 Q3 decided it (Alex 2026-10-29,
  "Ja machen wir"); the file is public on GitHub through the export today. Nothing moves.
- **T239.1 D2 (Alex, 2026-11-19): branch protection on `main`: a pull request with green CI for everybody else; the admin pushes
  directly.** The coordinating session pushes with Alex's account, so it pushes directly too. Pull requests from forks run on the
  builder's runner only after Alex approves them. Asked between "PR with green CI for all, you included", this, and "only block
  force-push and deletion"; Alex: "2".
- **T239.1 D3 (Alex, 2026-11-19): roles are mixed.** The two contributors who write code and build cores keep Write; every other
  tester moves to Triage (labels, closing, T238 triage) and works through forks, whose pull requests run only after approval
  (D2). Asked between "Write stays", "Triage" and "mixed"; Alex: "3" and named the two. Their handles are in the Gitea-only
  `.claude/context.md` (the public tree names no testers).
- **T239.1 D4 (Alex, 2026-11-19): two runners on the builder.** The Gitea runner stays for TREX/TRX64-Ultimate, a GitHub runner
  runs beside it for this repository; `/cache/heavy.lock` keeps one Vivado at a time across both. Moving TRX64-Ultimate to GitHub
  is a later, separate decision for that repository. Alex: "1".
- **T239.1 D5 (Alex, 2026-11-19): the private side repository takes only what is private; what helps contributors goes public.**
  Private (a Gitea repository, working name `TRX64U-MultiCore-private`): the ROM images (7 files), the bench media (12 files),
  the contact list, the T120 licence inventory, `.claude/context.md`, the hand-overs and the notes on internal infrastructure.
  Public: `CLAUDE.md` rewritten without internal infrastructure, the skills (`ux-review`, `fpga-gateware`), the agent
  (`ux-specialist`) and the architecture site (`.claude/trx64-site/`), so a contributor working with Claude Code follows the same
  rules (D24, spec-driven, style). Asked against "all of `.claude/` and `CLAUDE.md` private, as the export filter does"; Alex:
  "2". Fact corrected on the way: `.claude/` holds 16 tracked files (about 1.4 MB); the 149 MB on disk are untracked worktrees.
