## §1 The problem

- **Who:** the maintainer who changes the host menu, the SDK's base or a shared driver; the matrix; later the registry, which
  installs a host update.
- **What they try to do:** build the host as one more core (T239.3 D6, Alex 2026-11-22: "No. The host is a core. It has a bitstream,
  an app and sub-apps."): its app linked from the SDK package and its own libraries, tested by the matrix like the VIC-20 and the
  A1200, delivered on its own.
- **What happens today** (read from `t239.3`, 2026-11-25):
  - The host app has its own build: `host-app/target/u64ii/riscv/hostapp/Makefile`, 188 sources. 121 of them are the files the
    core app compiles too (Gideon's base, FreeRTOS, lwIP, LVGL, `uicore/`, `app/view|edit|video`, 16 files of `coreapp/src`:
    `appindex`, `cfgfile`, `corefolder`, `descrec`, `fastseek`, `fm_fs`, `fm_medium`, `httpreq`, `libload`, `libmenu`, `libscan`,
    `nettransport`, `ops`, `picmodes`, `svcjson`, `wsproto`). 67 are the host's own (64 in `hostapp/`, `fastseek_exports.cc`,
    `heap_4.c`). Both apps use the same linker script (`linker.x`) and the same heap (`configTOTAL_HEAP_SIZE=0x7A0000`).
  - `ci/trxapps.sh` (part `host`) builds it; the matrix's host lane calls that same build (`ci/lane.sh:62-70`), not the SDK
    package. The SDK release (`sdk-0.4.7`) holds no part of the host.
  - Alex placed the host's functions on the T239.3 discussion page (collection `place`): 9 from the SDK (service, loader,
    descriptor, screens, settings, F3 browser, picture, network, REST/RPC), 4 libraries of the host core (install; boot menu,
    `boot.cfg` and hand-over: 26 files, 13,487 lines; flash, update, restore, lock, `.cfw`: 17 files, 3,475 lines; the ESP32:
    7 files, 681 lines), no sub-app.
  - 102 files of `hostapp/` (14,734 lines) are on no row of that page: the host settings (`hostcfg*`), the host flows
    (`host_core_flow_*`: format, restore, Wi-Fi, zip, file operations, convert, ESP), video (`hostvideo*`), reports (`hostreport*`,
    `bugreport`), media (`mediaui`, `mediasniff`, `mediaglue`), the web UI (`webui`, `webnet`), `wifinet`, `discover`, `legacy*`,
    `startcheck`, `startfile`, `srcverify`, `cor`, `mbr`, `fmt*`, `menusnap`, `ftpstate*`, and their headers.
  - Shared code is compiled differently for the host: `TRX_HOSTAPP` in 18 places of 6 files outside `hostapp/`
    (`app/lib/appflags.mk`, `io/c64/keyboard_c64.h`, `io/network/network_esp32.*`, `io/wifi/wifi.*`). The SDK's base is compiled
    once, as link archives (T239.3 D31).
  - Boot: the boot ROM (`host/bootrom/bootrom.c`) loads the host app from the flash slot at 0x220000 in Gideon's format, at most
    1,966,068 bytes (`tools/check_app_size.py`), or over JTAG. `hostapp.app` of `t239.3` is 1.1 MB. A core app comes from its `.cor`.
  - Done already: the host's TOML A (`coreapp/gateware/host.toml`, 64 blocks, checked against `host/` by `tools/rtl_check.py`,
    T239.3 V-1); `basereg.def` is gone.
- **Why it matters:** a change to the base is built and tested twice, by two build files that drift; the host cannot go into the
  registry as a core (T239.4); T239.3 D6 stays a sentence.

Parts:
- **P1 Placement.** Every file of `hostapp/` is in the SDK, in a library of the host core, in a sub-app, or deleted.
- **P2 One base.** The base the host links is the base every core links: no host-only compile switch in shared code.
- **P3 TOML B of the host.** The host core's `sdk.toml`: its libraries, its base blocks, its tests.
- **P4 The link.** The host app is linked from the SDK package alone, as a core app is (`tools/sdk_core_app.sh`).
- **P5 Boot and image.** The boot ROM starts the linked app; the image fits the flash slot.
- **P6 Privileges.** Flash writes, ESP32 flashing and loading a core belong to the host's libraries only.
- **P7 Matrix.** The host lane runs steps 1-13 from the SDK, its tests from its TOML B.
- **P8 Same behaviour.** The host built this way does what today's host does: menu, boot, flash, network, REST.

## §3 Decisions

- **D1 (Alex, 2026-11-22, T239.3 D6):** the host is a core; its app is built from the same SDK as every other core; its boot menu,
  flash and Wi-Fi module code are libraries of the host core (T239.3 D10).
- **D2 (Alex, 2026-11-22, the discussion page):** the host's placement: 9 functions from the SDK, 4 libraries of the host core
  (install, boot menu, flash, ESP32), no sub-app.

- **D3 (Alex, 2026-11-25, Q1, translated: "Ok, all fits, your proposal is good I think"):** the 102 unplaced files of `hostapp/`
  go as proposed on the page's tab "Host on the SDK" (`.claude/trx64-site/app-architecture/hostrows.py`):
  - App start, LVGL setup, list window, pictograms (4 files, 420 lines): SDK - SDK: Start, run loop; Screens, views.
  - Host service: commands, key queue, model, page declaration (9 files, 2,148 lines): host library - Host library: the host core's descriptor and operations.
  - Host settings (3 files, 301 lines): SDK - SDK: Settings.
  - Video: HDMI mode, saved picture settings (3 files, 509 lines): SDK - SDK: Picture.
  - Wi-Fi: networks, join, status; FTP state (6 files, 1,292 lines): SDK - SDK: Network.
  - Web UI (4 files, 1,022 lines): sub-app - Sub-app of the host.
  - Reports: bug report, host report, log (7 files, 612 lines): SDK - SDK: F8 debug log.
  - File operations: copy, move, delete, zip (10 files, 1,631 lines): SDK - SDK: F3 browser.
  - Media: format, partition, file system check, medium info (17 files, 1,714 lines): host library - Host library: media.
  - Core files: read and verify a .cor, find bundles, icons (9 files, 1,078 lines): host library - Host library: boot menu.
  - Start: entry check, start record, config list, auto config, overlay text, menu snapshot (12 files, 1,648 lines): host library - Host library: boot menu.
  - Legacy firmware start (.cfw) (5 files, 734 lines): host library - Host library: flash.
  - Flash flows: restore, convert .cfw, confirm (6 files, 798 lines): host library - Host library: flash.
  - ESP32 flow (2 files, 315 lines): host library - Host library: ESP32.
  - Cores and ROMs: list, duplicates, delete (2 files, 286 lines): host library - Host library: install.
  - SHA-256, SemVer (3 files, 199 lines): SDK - SDK.
  The core app compiles nine `hostapp/` files already (they are in the SDK base): `bugreport`, `configlist`, `cor`, `mediasniff`,
  `mediaui`, `sha256`, `wifinet`, and outside the groups `bootcfg` and `handover`; so do the flash and ESP32 drivers (`flash.cc`,
  `s25fl_flash.cc`, `esp32.cc`: Q4).

- **D4 (Alex, 2026-11-25, Q2: "Exactly, please"):** the host core lives in `host/app/` (`sdk.toml`, `lib/`), beside its gateware in `host/`.
  `cores/*/` stays the layer-2 cores that `ci/lib.sh` and `tools/core_toml.py` read; no core tool needs an exception for the host.
- **D5 (Q3, answered by the code, 2026-11-25):** there is no host-only compile switch to remove. The core app sets `TRX_HOSTAPP=1` too
  (`host-app/target/u64ii/riscv/coreapp/Makefile:358`, and `app/lib/appflags.mk:17` for sub-apps), so the 18 branches in shared code are
  compiled the same in both apps: they separate our apps from Gideon's Ultimate app, not the host from the cores. P2 holds today; S2's lint
  keeps it.
