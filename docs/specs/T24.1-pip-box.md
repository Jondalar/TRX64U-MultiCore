# T24.1 — Live C64 picture box (picture-in-picture): hardware and register spec

**Status:** spec 2026-10-04. Nothing built, no RTL, no app code, nothing measured. Written so that
the emulator team (C64U_emu / UE2) can model the block ahead of the RTL.
**Resolves:** the "Open" paragraph of T24 §14 (where the reader sits, cost) and fixes the numbers §14
only sketched. Where this file and §14 differ, **this file wins** (differences: §12).
**Builds on:** `pix_layer.v` (page 6 of `trx_io`, 0x101A6000), `vic_scaler.v`, the still capture
(T12 §5.2), `mig_arb` client "v". **Needs first:** branch `still-60hz` merged (the 60 Hz still,
`STILL_STATUS` b2; T12 §5.2 "60 Hz", T40 §10.5). On `main` today the capture never completes at
60 Hz, so a box would show nothing there.
**Sources read:** `T24-lvgl-ui.md` §1/§5/§7/§14, `T24-ui-project-review.md`, `docs/lvgl_ui_project/`
(read only), `T12` §5.1-5.3 and §6, `T20` §11.3/§16.7, `T40` §4.4/§9/§10, ARCH §7.5/§15.3,
`pix_layer.v` (main and `origin/still-60hz`), `vic_scaler.v`, `trx_io.v`, `ddr2_port.v` (`mig_arb`),
`c64_text.v` (its page-6 decode).

**One sentence:** a new block `pip_box.v`, instantiated inside `pix_layer`, reads the last complete
still slot (4-bit C64 colours in DDR2) row by row over the existing "v" client, looks the colours up
in the C64 palette, scales them by an integer factor and **replaces the pixel layer's output inside
one rectangle** (a hardware hole, no colour key needed); the scaler, the ring and the still capture
are not touched.

## 1. Decisions (each with its reason)

| # | Decision | Reason |
|---|---|---|
| D1 | The reader sits in **`pix_layer`** (as a submodule `pip_box.v`), not in `vic_scaler` (§2) | `pix_layer` already has the DDR2 client, the frame-start latching, the register page, the blend and the slot signals (`st_done_slot`, count, 60 Hz flag); `vic_scaler` has no DDR2 port and sits *below* overlay and UI |
| D2 | The picture comes from the **still slot**, not the scaler ring | the ring holds 64 lines; a box needs the whole frame at any vertical position (§14); the still is that frame, already in DDR2 |
| D3 | **Hardware hole**: inside the box rectangle the box pixel replaces the UI layer pixel; `PX_KEY` is not involved | no anti-alias fringe, edges exact whatever LVGL draws; LVGL's placeholder (dark panel, text) stays as fallback on bitstreams without the box (CAPS) |
| D4 | The box **follows `PX_GALPHA`**: it enters the blend as the foreground pixel, `PX_KEY` is bypassed for it | UI fades (`PX_GALPHA` dips, T24 §8.1, T48) fade the box with the UI instead of leaving a bright rectangle; no extra blend, no extra DSP |
| D5 | Layer order: C64 -> `overlay.v` -> [UI layer \| box] -> `c64_text.v`. Nothing of the UI can be drawn over the box | the hole is a replacement, not a layer; a popup that overlaps the box needs the app to switch the box off (§9) |
| D6 | Source: **live = the last complete slot** (default). Fixed slot 0 / 1 is an extra, tear-free only with `STILL_CTRL` capture off or the machine paused | Timewarp needs no fixed slot: while scrubbing the machine is paused and each step's frame becomes the "last complete" slot (T20 §16.7); fixed slots serve hold/compare |
| D7 | Source **area is a crop rectangle** of the still (X, W, Y50, H50, Y60, H60), not a mode list; presets in §3 | one mechanism covers full 400 x 270, 384 x 270 and the 320 x 200 text area |
| D8 | Integer scale 1-3 (`PX_CTRL` encoding), horizontal repeat; vertical **Bresenham** so the **box size is the same in 50 and 60 Hz** | a 60 Hz still has 240 rows against 270; without the stretch the box would change height at every mode switch and the LVGL layout would jump |
| D9 | Position in **output pixels** (0-1919, 0-1079), unsigned; right/bottom overshoot is clipped, left/top negative is not representable | UI at scale 2 and `PX_POS` 0: output = 2 x UI pixel; the design has no scrolling box |
| D10 | Registers are **staged; a write to `BOX_CTRL` commits all of them**, applied at the next frame start | a move (position + size + source) is one frame, never half; `PX_*` have no such rule and a straddling write can show one odd frame |
| D11 | Picture pixels are **888 from the palette**, not through RGB565 | no quantisation, identical colours to the full-screen scaler |
| D12 | **No hardware border.** LVGL draws the frame line outside the rectangle | zero LUT; with a hole the rectangle's edge is exact, so a frame next to it has no fringe |
| D13 | **No new interrupt**: the commit applies at the frame start (`IRQ_CAUSE` b6 vsync exists), `BOX_SEQ` tells which picture is on screen | nothing to dispatch |
| D14 | A late or missing row shows **`BOX_FILL`** (RGB565 register), counted | stable look; the UI layer's "show what is below" would flash the full-screen picture inside the hole |

## 2. Where the reader sits (evaluation)

| | `vic_scaler` | `pix_layer` (**chosen**, as `pip_box.v` inside) |
|---|---|---|
| DDR2 | none. A new `mig_arb` client or a mux onto "v": top-level change, `tb_mig_arb`/`sim/lat` re-proven | "v" client present; one more request channel in `ui_clk` (about 60 LUT) |
| Z-order | scaler output is **below** `overlay.v` and the UI layer: the UI must cut a key-colour hole over it (AA fringe, exact RGB565 match, T24 §14 rules) | box replaces the UI pixel: hole by construction, above overlay |
| Alpha | UI alpha blends over the box; the box cannot follow fades | box is the blend's foreground: follows `PX_GALPHA` |
| Frame timing | scaler locks once to the VIC (`frame_tgl`, `locked`); a window mode multiplies its 50/60 Hz cases | `pix_layer` already re-derives everything at `cy = 0, cx = 8` of each frame |
| Slot data | needs slot/mode/count carried over from `pix_layer` | same module: `st_done_slot`, `st_done_60`, `n_still` are local |
| Registers / CAPS | new page-6 block anyway | same block, same commit rule |
| Palette | has Colodore | needs a copy (rule: one shared function, see §6.5) |
| Risk | touches the module that drives the HDMI timing | `pip_box.v` is new; `pix_layer`'s tested paths change only by a 24-bit mux at stage E4 and an `on` term |

Cost of the choice: `pix_layer` roughly doubles (about +450-600 LUT, §8). A separate module keeps the
tested `pix_layer` bench valid with `BOX_CTRL` = 0.

## 3. The picture: what the still holds, areas and sizes

Facts (code, not comments): the still window is X0S = 96, Y0S = 16 of the VIC pixel stream. 50 Hz
slot: 400 x 270, 3,375 words (word k holds pixels 32k..32k+31, pixel j of a word at bits
4j+3:4j, two pixels per byte, first in the low nibble), row pitch 400 pixels = 12.5 words (rows are
**not** word aligned: odd rows start at nibble 16). 60 Hz slot (`still-60hz`): 400 x 240, 3,000 words,
same packing and pitch; its rows 0-231 are raster lines 31-262 and rows 232-239 are lines 0-7 of the
next frame (T12 §5.2). A slot is at `STILL_BASE + slot x 0x10000`. The text area (320 x 200) sits at
still x = 40 (`x_text` 136 minus X0S 96, T40 §10.3), still rows 35-234 at 50 Hz (raster 51-250 minus
16) and rows 20-219 at 60 Hz (raster minus 31). The border is 40 / 35 pixels, symmetric.

| Area (preset) | crop x, w | y50, h50 | y60, h60 | box 1x out / UI | 2x out / UI | 3x out / UI |
|---|---|---|---|---|---|---|
| **FULL** (default; what the full-screen picture shows) | 0, 400 | 0, 270 | 0, 240 | 400 x 270 / 200 x 135 | 800 x 540 / **400 x 270** | 1200 x 810 / 600 x 405 |
| TRIM 384 x 270 (border 8 px narrower each side) | 8, 384 | 0, 270 | 0, 240 | 384 x 270 / 192 x 135 | 768 x 540 / 384 x 270 | 1152 x 810 / 576 x 405 |
| TEXT (320 x 200, no border) | 40, 320 | 35, 200 | 20, 200 | 320 x 200 / 160 x 100 | 640 x 400 / **320 x 200** | 960 x 600 / 480 x 300 |

"384 x 272" (T24 §14 text, the UDP stream's size) is **not offered**: the still has 270 rows. UI
size = output size / 2 (UI scale 2, `PX_POS` 0).

Box output size, all modes: **Wo = W x S, Ho = H50 x S.** In 60 Hz the H60 source rows are stretched
to Ho lines (FULL: 240 -> 270 x S). Valid only with W >= 1, X + W <= 400; H50 >= 1, Y50 + H50 <= 270;
H60 >= 1, Y60 + H60 <= 240, **H60 <= Ho** (no row skipping).

**Stretch rule (bit exact).** At the box's first line: `row = 0, acc = 0`. At each following box line:
`acc += Hm; if (acc >= Ho) { acc -= Ho; row += 1 }`, Hm = H60 for a 60 Hz slot, H50 for a 50 Hz slot,
Ho = H50 x S. Source row `row` (+ Ysel) is shown on that line. 50 Hz: each row S times. 60 Hz FULL
at S = 2: 540 lines for 240 rows, pattern 3, 2, 2, 2 (T12's software path uses 2, 2, 2, 3; not
compared). Text preset: Hm = Ho / S in both modes, plain repeat.

## 4. Geometry: output pixels and UI pixels

Output pixel (x, y) of the 1920 x 1080 active area = (cx - 768, cy - 45) (same as `PX_POS`).
UI at scale 2, `PX_POS` = (0, 0): `box_x = 2 x ui_x`, `box_y = 2 x ui_y`; in general
`PX_POS + PX_scale x ui`. The app reads the placeholder object's absolute coordinates after layout
(`lv_obj_get_coords`) and writes `BOX_POS`. Even coordinates keep the box on the UI pixel grid; the
hardware does not require it. The rectangle is `[x0, x0 + Wo) x [y0, y0 + Ho)`; pixels beyond
x = 1919 or y = 1079 are clipped; `x0 >= 1920` or `y0 >= 1080` = not drawn (BADGEO).

## 5. Register block (page 6, 0x101A6000 + offset)

Free space: `pix_layer` uses 060-068, 080-0A4; `c64_text.v` decodes 0C0-0C7. The box takes
**0E0-0FF** (`addr[11:5] == 7'b0000111`), read data OR-ed into the page-6 read bus like `c64_text`.
Bus rules as for all page-6 registers: 32 bit little endian, a write of byte 3 commits the four
bytes, a read of byte 0 latches the four bytes; unused bits read 0, writes ignored.

| Off | Name | R/W | Bits | Reset |
|---|---|---|---|---|
| 0E0 | `BOX_CTRL` | RW | b0 EN; b2:1 SRC (0 live = last complete slot, 1 slot 0, 2 slot 1, 3 = live); b5:4 S (0 and 1: 1; 2; 3); **writing it commits** (below) | 0 |
| 0E4 | `BOX_POS` | RW | b15:0 x0, b31:16 y0 (output pixels, unsigned) | 0 |
| 0E8 | `BOX_SRC_X` | RW | b15:0 crop x, b31:16 crop width W (still pixels) | x 0, W 400 |
| 0EC | `BOX_SRC_Y50` | RW | b15:0 crop y, b31:16 height H50 (rows of a 50 Hz slot) | y 0, H 270 |
| 0F0 | `BOX_SRC_Y60` | RW | b15:0 crop y, b31:16 height H60 (rows of a 60 Hz slot) | y 0, H 240 |
| 0F4 | `BOX_FILL` | RW | b15:0 RGB565 fill colour (widened by bit replication) | 0x0000 |
| 0F8 | `BOX_STATUS` | R | b0 VALID (`STILL_STATUS` b0 at the last frame start); b1 SLOT shown; b2 M60 shown slot is 60 Hz; b3 ACTIVE box was drawn last frame; b4 BADGEO committed geometry invalid; b5 FILLONLY last frame showed fill only; b15:8 underrun rows (wrapping); b31:16 frames drawn (wrapping) | 0 |
| 0FC | `BOX_SEQ` | R | b23:0 `STILL_STATUS` b31:8 of the picture shown in the last frame (0 while fill only) | 0 |

Presets as register values (write the five, then `BOX_CTRL`):
FULL: SRC_X 0x0190_0000, Y50 0x010E_0000, Y60 0x00F0_0000 (the reset values).
TEXT: SRC_X 0x0140_0028, Y50 0x00C8_0023, Y60 0x00C8_0014.
TRIM: SRC_X 0x0180_0008, Y50 0x010E_0000, Y60 0x00F0_0000.
(Hex = {H or W 16, y or x 16}.)

**Commit and latch.** Writes to `BOX_POS`..`BOX_FILL` change the staged values (readable at once) and
nothing on screen. A write to `BOX_CTRL` (byte 3) publishes the staged set and the control bits; the
publish is carried to the pixel clock with the same toggle scheme as `cfg_tgl` (copies `c_*`), and
the values are taken into the per-frame set `f_*` at `cy = 0, cx = 8`, with the other `PX_*`. So:
the picture changes at the next frame start after the commit, never inside a frame. To change only
the position, write `BOX_POS`, then `BOX_CTRL` again with the same value. `BOX_FILL` is taken with
the set. `STILL_BASE` is taken from its register at the same instant (change it only with the box
off). The per-frame source tuple (slot, M60, sequence, valid) is read at the same instant from the
`pix_layer`'s `still_*`/`n_still` registers (crossed like `p_cfg`; they change only when a capture
completes, which locked is >= 34 VIC lines away from `cy = 0`, §7.4).

Detection: CAPS2 (0x005) is full once T29 (b6 turbo) and T21 (b7 trace former) are merged (0xFF), so the box takes **CAPS3 (0x006) b0** = box present (a new read-only byte in `trx_io.v`; 0 on older builds). Gideon's
bitstream and older builds read 0 there and in the whole block.

## 6. Pipeline and DDR2

### 6.1 Compositing (hole, alpha, key)

The UI pipeline of `pix_layer` is E0-E8 (line buffer E1/E2, lane E3, key E4, `fg - bg` E5, product
E6/E7, add E8). The box adds:

- a box row buffer and counters running in the same `cx_in`/`cy_in` frame as the UI's (own
  `box_h_on`, `box_x`, sub counters; same one-clock-per-stage discipline);
- at E3 the palette lookup of the box pixel (24 bit); at E4 a mux: `fg888 = in_box ? pal888 : widen(fg5)`;
- `on5 = (h_on_ui && !key_hit) || in_box` where `in_box` (box row valid or fill) **bypasses the key**,
  and the UI's `h_on`/`line_ok` do not matter inside the rectangle;
- the blend (`out = bg + a (fg - bg) / 256`, `a = PX_GALPHA + bit 7`) is unchanged and applies to the
  box pixel. With `PX_GALPHA` = 255 the box is opaque; with 0 the full-screen picture below shows.

So the box works with the UI layer **disabled** (`PX_CTRL` b0 = 0): `on5` is then box only, and the
blend uses `f_ga` of the committed `PX_GALPHA` as usual.

### 6.2 What is in the rectangle when there is no picture

`BOX_FILL`, at the blend's foreground, for: `STILL_STATUS` valid = 0; a row that was not in when its
line started (never shown in part: the whole row line is fill, counted in `BOX_STATUS` b15:8); a fixed
slot is never checked (it shows whatever the DDR2 holds: the app captures first).

### 6.3 DDR2 format and fetch

Box row `r` of the output (after the stretch rule) selects source row `q = Ysel + row`, with `Ysel` =
Y50 or Y60 by the slot's mode flag:

```
k0   = 400 * q + X                    // pixel index in the slot (running add of 400 per source row)
word = k0 >> 5 ; n0 = k0 & 31         // first 128-bit word, nibble offset of the first pixel
nw   = ((n0 + W - 1) >> 5) + 1        // words to read, at most 14
addr = STILL_BASE + slot * 0x10000 + 16 * word        // nw reads back to back
pixel i of the row: idx = n0 + i, word idx >> 5 of the buffer, lane idx & 31 -> bits 4*lane+3 : 4*lane
```

The row buffer holds two rows (ping-pong) of at most 14 x 128 bit. A source row is fetched **once**
and shown for its S output lines (or, stretched, for 1-3 lines), so reads per frame do not depend on S.
When box row m starts on the screen, row m+1 is requested into the other half (as `pix_layer` does for
UI lines); the first row is requested at `cy = 0, cx = 400` (after the UI's line 0 request at cx 12).
Requests go to the "v" client through a second request channel; a UI line fetch is never aborted by
a box request and the reverse. UI lines go first in `ui_clk` (their 5.3 us `v_urgent` rule stays);
the box row has the whole output line (17.7 us at 50 Hz, 14.8 us at 60 Hz) and needs 13 reads,
about 0.2 us. The slot is read with the box's own tuple from the frame start; the mode flag selects
Ysel/Hm for the whole frame.

### 6.4 Pixel stage

`lane`-select as the UI's E3, from the box's row buffer; 4-bit colour into `palette()`; the horizontal
repeat counter is the UI's (`hsub`).

### 6.5 Palette

The Colodore table of `vic_scaler.v` (below). Rule for the RTL: **one function** in a shared include
(`c64_palette.vh`) used by scaler and box; a copy would drift the day the scaler's palette becomes
selectable.

| 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|
| 000000 | FFFFFF | 813338 | 75CEC8 | 8E3C97 | 56AC4D | 2E2C9B | EDF171 |

| 8 | 9 | 10 | 11 | 12 | 13 | 14 | 15 |

| 8E5029 | 553800 | C46C71 | 4A4A4A | 7B7B7B | A9FF9F | 706DEB | B2B2B2 |

## 7. Behaviour in the awkward cases

### 7.1 Machine paused, frozen, scrubbing

The pause stops the VIC and with it the capture; `STILL_STATUS` keeps naming the last complete slot,
which nothing writes. The box shows that picture, frozen. The full-screen scaler is black while the
machine is halted (`blank`), so with a UI open over a paused machine the box is the only picture.
**Timewarp:** a scrub step restores, runs one frame and stops on line 0 (T20 §16.7); that frame
completes in the other slot and becomes "last complete": the box shows it from the next frame start
(1-2 output frames later). The app knows the step is on screen when `BOX_SEQ` equals the
`STILL_STATUS` count it read after the step. No fixed slot, no extra path (T20 §11.3). The ring
frame's picture is "frame T plus one frame of running" as T20 §16.7 says; unchanged.

### 7.2 Owner rule (T24 §7)

The box block belongs to whoever owns the layer: `trx_lv_yield_layer()` (the freeze entering) must
also write `BOX_CTRL` = 0, and T12's freeze renderer never writes it. LVGL sets the box up when it
takes the layer back. A box left on by mistake is visible, not harmful (it covers a rectangle of the
freeze menu's UI layer; `c64_text.v` is above it).

### 7.3 50/60 Hz

The source mode is **per slot** (`still_60`, latched with the slot at the frame start), never the live
`v60`: a slot written in the old mode stays valid and is decoded with its own flag until a new-mode
frame completes, so the box never mixes modes inside a frame. Output counters are mode independent
(`cx` 768..2687 at both). A mode switch resets the pixel clock side (T40 §9.3, about one second of
black HDMI): `pix_layer` re-derives all per-frame state at each `cy = 0, cx = 8`, so after a
discontinuity the box recovers within one frame; the app may also switch the box off for the switch.
A mid-frame switch of `v60` changes nothing inside the frame being drawn.

### 7.4 Tearing (double buffer), analysis

Derived from `vic_scaler.v` (output line 0 = cy 45 starts when the VIC reaches raster line 20 at 50 Hz
and line 35 at 60 Hz, locked once and kept: 125/26 and 990/263 clock ratios) and `pix_layer.v`
(capture start and completion lines):

- **50 Hz.** `cy = 0` is 45 output lines = 12.5 VIC lines before line 20, i.e. at raster line 7.5. The
  slot L that completed at line 285 of the previous frame is latched 34.5 lines (2.2 ms) after its
  completion; the capture of the current frame starts at line 16 (8.5 lines after `cy = 0`) and writes
  the *other* slot, completing at line 285, i.e. after the box's whole frame (20 ms) has started, and
  the slot L is rewritten only from line 16 of the frame after. The box reads L during `[t0, t0 + 20 ms]`,
  the writer touches L from `t0 + 20 ms + 8.5 lines`. **No overlap; tear-free by phase lock.**
- **60 Hz.** `cy = 0` is at raster line about 24.5; the slot completes at line 262 and the capture of
  the next frame starts at line 0 of the next frame (rows 232-239 first). The writer touches the slot
  the box is reading only from line 0 of the second frame after, i.e. 238.5 lines after `cy = 0`;
  the box's last line is output line 1124 = 263 lines. **Overlap only if the box reaches output lines
  about 1019-1054** (its rows 232-239, border) **at 60 Hz**: those 8 rows may show the next frame's
  top border. Rule: a box at 60 Hz ends above output line 1019 (UI line 509); all of the design does.
- Age of the picture: **1-2 frames** (19-39 ms from the VIC drawing a row to the box showing it).
- The argument needs the scaler locked and the VIC resuming after whole frames (`c64_core` does,
  `vic_scaler.v` header). Not locked (first frames, mode switch): possible tear for a frame; the sim
  proves both cases (§10).
- Fixed-slot modes: the capture keeps writing the other slot; reading a fixed slot is tear-free
  only with `STILL_CTRL` capture off or the machine paused.

### 7.5 Box partly off-screen, overlapping others

Right/bottom: clipped by the active-area counters; rows past the bottom are not shown (one extra row
fetch at the end is harmless, its address stays inside the slot). Left/top negative: not representable;
the app switches the box off when a scroll takes it out. `x0 >= 1920` or `y0 >= 1080`: not drawn
(BADGEO). Two overlapping things: the box wins over the UI layer (D5); `c64_text.v` wins over the box.

## 8. Cost (all of it an estimate, to be replaced by the first synthesis report)

**DDR2 reads (box only, per frame, independent of S):**

| Crop | words per row | rows | reads / frame | bytes / frame | MB/s |
|---|---|---|---|---|---|
| FULL 50 Hz | 13 | 270 | 3,510 | 56.2 KB | 2.8 (50.12 Hz) |
| FULL 60 Hz | 13 | 240 | 3,120 | 49.9 KB | 3.0 (59.83 Hz) |
| TEXT | 11 | 200 | 2,200 | 35.2 KB | 1.8 / 2.1 |
| worst crop (14 words) | 14 | 270 | 3,780 | 60.5 KB | 3.0 |

Together with the UI scanout (52 MB/s at 960 x 540), the still write (2.7) and the box: about 58 MB/s,
**4.8 %** of the MIG peak (1.2 GB/s, T20 §5.4). T24 §14's 2.7 MB/s counted 54,000 B/frame without
the row misalignment. Per row 13 reads at 13.3 ns = 0.17 us.

**Logic (estimate):**

| Part | LUT |
|---|---|
| registers: staged 7 x ~24 b, committed copies, frame set; read mux; write decode | 110 |
| rectangle compare, row/column counters, Bresenham accumulator | 100 |
| source address (k0 running add, nw, 28-bit address) | 75 |
| `ui_clk` request channel and counters | 60 |
| row buffer 2 x 14 x 128 b as LUTRAM, lane mux 128 -> 4 | 130 |
| palette 16 x 24, E4 mux, pipeline registers | 60 |
| CDC toggles/syncs | 30 |
| **Total** | **~450-600 LUT, ~500-650 FF, 0 DSP** |

Row buffer alternative: two RAMB36 (128 bit wide, the pattern of the UI's 256 x 128): -90 LUT, +2
BRAM. Recommend LUTRAM (BRAM is not scarce on the 50T, but a 4 kbit buffer in two 36 kbit blocks is
waste). About 1.5-2 % of the 50T's LUT. ARCH §11 budgets the whole video part at ~500 LUT / 2 BRAM /
3 DSP: the box roughly doubles the LUT figure. Timing: no new multiplier; the added mux sits in
front of the E5 subtractor's register (E4 -> E5 path unchanged in depth).

## 9. Rules for the LVGL design

- Every box is a **`pip_slot`** component: an `lv_obj` of exactly the sizes in §3, radius 0, no
  border, outline, padding, shadow or text on it. Its fill is the placeholder (dark panel); the
  hardware replaces it when the box is on. The app places the box from the object's coordinates.
- Nothing is drawn **over** the rectangle (labels, chips, focus rings, popups); the hardware hides it.
  The frame line is a sibling drawn outside the rectangle. A modal that overlaps a box: the app
  switches the box off for as long as the modal is open (or the modal avoids it).
- One box at a time (one register set).
- Sizes in UI pixels (UI 960 x 540 at scale 2): **2x FULL = 400 x 270, 1x FULL = 200 x 135**; TEXT
  2x = 320 x 200, 1x = 160 x 100; TRIM 2x = 384 x 270, 1x = 192 x 135. 3x does not fit any screen
  (600 x 405 against a 776 x 440 content area with a title row). At 400 x 270 the box covers
  21 % of the screen: "dominant surface" (`UI-SCREEN-TOUR.md`) is as big as this hardware goes.
- Sizes are the same in 50 and 60 Hz (D8): no relayout at a mode switch.

## 11. Emulator (UE2) modelling notes

UE2 must implement, in this order of importance:

1. **Registers** 0E0-0FC with the commit rule (staged until `BOX_CTRL` is written; published at the
   next emulated frame start), reset values, CAPS3 b0, read-only fields, 32-bit bus rules as page 6.
2. **Frame composition:** at each emulated output frame start take the committed set and the tuple
   (valid, slot = last complete, M60 of that slot, `STILL_STATUS` count). Read the slot from the DDR2
   model at `STILL_BASE + slot x 0x10000` (3,375 / 3,000 words), decode nibbles (low nibble first),
   apply crop, `Ysel`, the **stretch rule** (§3) and the horizontal repeat; look up the Colodore table.
3. **Compositing:** the box pixel replaces the UI pixel in the rectangle (UI value and `PX_KEY` ignored),
   then `out = bg + a (fg - bg) / 256`, `a = PX_GALPHA + bit 7`, **fg = palette 888, not RGB565**;
   outside the rectangle the UI layer as today; the text layer above everything; box works with
   `PX_CTRL` b0 = 0. Clip right/bottom; BADGEO rules of §3-§4.
4. **Source semantics:** live = the slot `STILL_STATUS` names *at the frame start* (so the box is one
   frame older than a UI the app draws in the same frame); fixed slots read the named slot without
   validity; no valid frame = fill; paused machine = last slot, unchanged; a 50/60 mode switch keeps the
   old slot decoded with its own flag.
5. **Status:** `BOX_SEQ` = count of the shown picture; `BOX_STATUS` bits; frames-drawn counter;
   underrun always 0 (UE2 has no DDR2 starvation).
6. **Sizes:** `Wo = W x S`, `Ho = H50 x S` in both modes.
7. **Not modelled:** tearing (§7.4 shows none by construction), the line buffers, DDR2 timing, the
   exact 60 Hz rows 232-239 exception (state it in the emulator's notes as a known difference).
8. UE2's still capture must produce the 60 Hz slot (`still-60hz` semantics) or the box has nothing to
   show in 60 Hz modes.
