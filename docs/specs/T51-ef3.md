# T51 — EasyFlash 3 emulation, writable 8 MB

**Status:** spec 2026-10-07 (overnight build), branch `t51-ef3` (superproject), `t51-ef3-app` (app). **Task:** TODO.md T51.
**Sources read:** PROP-002 §8.4 (CRT type 90, agreed with TRX64), T33 (descriptor decoder), T60 §7 (shared 16 MB block, ROM_SEL),
T16.2 (flash write-back), `~/.claude/EF_GEOMETRY.md`, skoe's EF3 CPLD sources, EasySDK `eapi-mx29640b.s`, EF3BootImage, Macronix
MX29LV640E T/B data sheet v1.7. Evidence rule: code and data sheet, not comments.

## Scope (Alex, 2026-10-07; overrides everything below where it differs)

1. **In the generic cartridge decoder, not a dedicated block.** D1 is reversed: EasyFlash 3 is driven purely by its descriptor
   (T33 / PROP-002 §8.5). The generic decoder gained what banking needs, usable by other types: a third register R2, rules and
   fields that can name it, a 9-bit bank, an IO1 read of R2, the chip-order flash address (PROP-002 §10, descriptor v2). `c64_ef3.v`
   is **deleted** from the tree (it no longer fits the scope: its job was the menu modes); it stays in git history and in the tag below.
2. **Banking and EasyFlash only.** In: `$DE00` bank (6 bit), `$DE01` slot (3 bit, reads back), `$DE02` control as the EasyFlash,
   IO2 RAM, the 8 MB image window, the MX29LV640 flash (autoselect, program, 8 KiB boot-sector and 64 KiB sector erase, **faithful
   chip erase of the whole 8 MB**, EAPI of the image, write-back), CRT type 90 load and save. **Out (not built, Alex decided):** the reset-
   surviving mode machine, `$DE0F` modes (KERNAL mode, freezers AR/RR/NP/SS5, kill), the KERNAL replacement (`kovr` in PLA, arbiter,
   turbo, c64_top: reverted), the EF3 menu / system-area boot, `$DE08/$DE09/$DE0A` (version, USB), the no-VIC bit of `$DE02` (as in the
   EasyFlash descriptor), the generated C64 reset, the three buttons and the app actions "EF3: Menu / Reset Slot / Reset, No Boot".
3. **trex_crt (real carts):** dump a complete EF3 as one type 90 CRT (slot 0 included), erase a whole real EF3, write a type 90
   image (the way back after a whole-cart erase). Dumping is reading banks, so it works with the reduced emulation scope.
4. Full EF3 emulation (menu, modes, KERNAL replacement, dedicated block, buttons) is **parked at the tags `park/ef3-full`
   (superproject) and `park/ef3-full-app` (app)** (Alex 2026-10-07: keep it in git).
5. **Start slot: decided (Alex 2026-10-07), no start-slot feature.** After a load the emulation starts slot 0 (descriptor `R2_INIT` = 0); a program switches slots with `$DE01`.
   **Recorded difference to a real EF3:** a real EF3 keeps the slot it was set to (by its menu) until power-off; ours returns to slot 0 on every C64 reset (the decoder keeps no state across resets).
   Accepted. Alex's real goal: not to use the EF3 in the simulation, but to debug his EAPI bug **with the real EF3 in the port (T16) and the monitor**; the emulation is secondary.

## 1. What an EF3 is (from the sources)

| Fact | Evidence |
|---|---|
| 1 flash MX29LV640E**B**T: 8 MB, x8, **bottom boot**: 8 x 8 KiB sectors at 0x000000-0x00FFFF, then 127 x 64 KiB; byte-mode autoselect: manufacturer `$C2` at A0=0, device `$CB` at address `$02` (EB = bottom, ET = top: ET reads `$C9`); unlock cycles `$AAA` / `$555` | data sheet (ordering code, ID table, "outermost boot sectors ... lowest addresses" for EB); EAPI `MX29LV640EB_DEV_ID=$cb`, reads `$8000`/`$8002`; `eapi.s` "bank 0 erase = 8 boot sectors" |
| Flash address (23 bit) | `ef3.vhdl set_mem_addr`: `{slot(3), bank_hi(3), n_roml(1: 0 ROML, 1 ROMH), bank_lo(3), A12-A0}`. A 64 KiB sector = 8 banks of **one half** of one bank_hi group (EF_GEOMETRY "Löschgeometrie") |
| `$DE00` write | `bank_hi <= D5:3`, `bank_lo <= D2:0` (only in EF mode); not readable |
| `$DE01` | R/W slot (3 bit), EF mode only; read returns the slot |
| `$DE02` | EF1 control: D0 GAME, D1 EXROM, D2 M (0: GAME = boot flag), D3 no-VIC (lines inactive in phi1), D7 LED. Reset: EXROM 0, GAME = boot flag (1) = Ultimax boot. Boot flag: set by sys reset / menu / button B; cleared by button C ("special") |
| `$DE08` read `$49`, `$DE09` read `{!rxf, !txe, 000000}`, `$DE0A` USB data | `cart_usb.vhdl` (EF and KERNAL modes) |
| `$DE0E` write | KERNAL bank_lo (KERNAL mode only) |
| `$DE0F` write | mode, only while the menu is active: 0 EF + reset, 1 EF without reset (register hidden), 2 KERNAL + reset, 3 (FC3) nothing (all disabled, no reset), 4 AR/RR/NP + reset, 5 SS5 + reset, 6 C128 (all off, reset, go to C128), 7 all off + reset |
| `$DF00-$DFFF` | 256 bytes RAM, EF and KERNAL modes (`cart_io2ram`: SRAM A12..A0 = `$1Fxx`) |
| KERNAL mode | on a read of `$E000-$FFFF` with HIRAM the CPLD answers from flash `{slot, bank_hi, 0, bank_lo, A12-A0}` (ROML half, 8 KiB per bank_lo) by an EXROM/GAME trick; flash address uses slot/bank_hi as left by the menu |
| Resets | system reset (C64 reset line) -> EF + menu active, slot 0, bank_hi/lo 0, boot flag 1. Generated reset (7 phi2 cycles, `$DE0F` write, buttons B/C) keeps slot, mode and bank_lo; `ctrl_*` return to reset values; button B/C also clear bank_hi/bank_lo. Button A = back to the menu (as a system reset) |
| Slot layout (EF3BootImage) | slot 0 = system area: banks 0-7 ROML = KERNALs (exactly the 8 boot sectors), bank 0 ROMH `$1F00` trampoline, 8 menu, 11 prgstart, `$10` ROML "EF-Directory V1:", `$18-$1F` AR, `$20-$27` SS5. Slots 1-7: plain EasyFlash (type 32) images, EAPI at bank 0 ROMH `$1800` |
| Not on this hardware | USB (FT245), the three buttons, LED, freezer button |

## 2. Decisions (state 2026-10-07 after Alex's reversal and scope correction; D-numbers as before)

D1. **Generic descriptor, not a dedicated block** (reversed 2026-10-07; the first build had `c64_ef3`, parked). New descriptor features, PROP-002 §10: a third
register R2 (reset value, write mask), rules and fields that can name R2, `BANK9`, an IO1 read of R2, `FSPLIT3`. The decoder grows by +61 LUT / +10 FF (§8).

D2. **Image layout.** CRT type 90, CHIP packets slot-major, 8 KiB each, bank field = `slot*64 + bank` (0..511), PROP-002 §8.4. DDR2: 16 KiB per bank slot, ROML at
`n*16K`, ROMH at `+8K`: 8 MiB at the block base `0x1000000` (ROM_SEL 1). Image offset = `{slot, bank6, romh, A12-A0}`. Header EXROM 1 / GAME 0.

D3. **Window 8 MB.** `TRX_XPORT_ROM_MAX_EF3` 8 MB (other types stay 4 MB). `cart_slot`'s request address is 24 bit: b22 stays "cartridge RAM", **b23 is image offset bit 22**;
cache tag 13 bit. ROM_SEL 0 (Gideon's `0x3C00000`, 4 MB) stays 4 MB: the app refuses type 90 without `XPORT_CAPS`.

D4. **The flash responder sees chip order.** `c64_flash_amd` gets the 23-bit chip address `{slot, bank_hi, romh, bank_lo, A12-A0}` (descriptor `FSPLIT3`); address and event
address are 23 bit, the event word 34 bit (EVT +024). The app converts chip address to image offset (a bit permutation) and knows the sector map (8 x 8 KiB + 127 x 64 KiB).
Unlock `$AAA/$555`, mask `$FFF`, IDs `$C2/$CB`, ID address 2.

D5. **Chip erase is faithful** (Alex 2026-10-07; the refusing guard of the first build is gone): `$AA,$55,$80,$AA,$55,$10` erases the whole 8 MB image (`trx_erase_span`).
Recovery after that is writing a system image back to slot 0 (emulation: load a type 90 file, `tools/ef3_image.py system IMAGE SYSTEM -o OUT`; real cart: trex_crt writes a type 90
image, §4). With Auto write-back an erased image is saved to its file; keep another copy of the base image.

D6-D9, D12 (KERNAL mode through the PLA, resets/buttons, modes 3-7, USB, EF3 state-bus word): **not built, parked** (scope item 2). `st_bank` is `{0, R2[2:0], R1[7], R1[2:0], R0}`.

D10. **EAPI.** The images carry their own MX29LV640 EAPI per slot (EasyProg writes it); the app does not patch it for type 90. A type-32 EasyFlash goes into a slot with
`tools/ef3_image.py insert` (EAPI replaced by skoe's MX29LV640 driver as EasyProg and trex_crt do).
**Amended (Alex 2026-10-10):** no EAPI substitution anywhere in emulation: the cartridge layer models the chip from the descriptor and answers the CRT's own EAPI, so `patch_easyflash_eapi`/`_eapi_65` leave our app. A swap only where a real chip differs: the writer puts the MX29LV640 EAPI in when writing an EasyFlash image to a real EF3; the dumper puts the AM29F040 EAPI in when it dumps one EF3 slot as type 32 (EXROM 1, GAME 0, chip type 2, as `ef3_image.py extract`). The whole-EF3 type 90 dump stays a 1:1 copy.

D11. **CART_TYPE 0x12.** Descriptor `tools/cart_descriptors/12_easyflash3.json`; requires `CART_UCI_DE1C` (UCI at `$DE1C`), prohibits IO and the REU (rule "REU or cartridge").

D13. **Write-back** as for every flash cartridge (dirty map of 1024 blocks, `save_crt` writes 1024 CHIP packets slot-major = 8.4 MB, 8 MB snapshot buffer for the unattended save).

## 3. Hardware (as built)

- `c64_cartridge.v`: R2 with `R2_INIT`/`R2_WMASK` (bytes 38/39), `REGX` (37) giving the field and rule register numbers a second bit, 9-bit bank (`EXT` b1), IO1 read of R2
  (`RD_MATCH/RD_MASK`, `EXT` b0), flash chip address with ROMH above bank bit 3 (`EXT` b2); descriptor 43 bytes, trx_io window 0x040-0x06A. Bytes 37-42 = 0 is the old descriptor.
- `c64_flash_amd`, `c64_cartridge`: 23-bit chip address and event address; event word 34 bit. `cart_slot`: 24-bit request address, 13-bit tag, queue 40 bit. `cart_fill`:
  ROM base + `{a23, a21:1}`. `dma_win`, `c64_core`, `top.v`: widths. `trx_io`: EVT +024 (EVT_HI), XPORT_CAPS +038 (b0 8 MiB window, b1 EasyFlash 3 banking; older bitstreams read 0).
- Removed again (parked): `c64_ef3.v`, `kovr` in `c64_pla`/`c64_bus_arbiter`/`c64_turbo`/`c64_top`, `rst_req` into `c64_core`, the buttons (`cart_slot`, `trx_io` +034).

## 4. App (as built)

Firmware (`software/io/c64`): `c64_crt.cc` type 90 -> `CART_EASYFLASH3`, 512 banks, no EAPI patch, `SSRET_NOT_IMPLEMENTED` without `trx_ef3_present()`, window 8 MiB for type 90 only, saved as 1024
packets in bank order; `trx_cart.cc`: 8 MiB image and dirty map, EVT_HI, `trx_flash_geom.h` (permutation, sector map, `trx_erase_span`: a chip erase is the whole 8 MiB), `trx_ef3_present()`;
`trx_cart_desc.h` regenerated (43 bytes). No menu actions.

**trex_crt** (`apps/trex_crt`, real EasyFlash 3 in the port, both cores):
- **Dumper.** F7 picker (same in dumper and writer): slots 1-7 and "Full EF3 (all slots, type 90)". All slots = one CRT of type 90, header EXROM 1 / GAME 0, 1024 CHIP packets (flash type 2) slot-major, packet bank =
  `slot*64+bank`, ROML at `$8000`, ROMH at `$A000` (read at `$E000`). Read order: for slot 0..7, `$DE01` = slot, for bank 0..63: `$DE02 = $05` (Ultimax), `$DE00` = bank, ROML 8 KiB at `$8000`, ROMH 8 KiB
  at `$E000`. **How slot 0 and every slot are visible on a real EF3** (skoe's `cart_easyflash.vhdl`, `ef3.vhdl set_mem_addr`): `$DE01` bits 2:0 are the slot, `$DE00` D5:3 `bank_hi` and D2:0 `bank_lo`,
  flash address `{slot, bank_hi, n_roml, bank_lo, A12-A0}`, with the cartridge in EF mode, which is the state after power-on and after the menu button, and stays so after the menu started a slot
  (`$DE0F` = 0/1); slot 0 is selected like any other, nothing hides the system area (the menu hides nothing, it is just code in it). Not readable this way: in KERNAL mode (menu keys 1-3, `enable_ef` = 0 the EF registers
  are gone), a freezer mode, or after a program wrote `$DE02` = `$04` (off). trex_crt then sees no EF3 (`$DE01` does not read back) and says so; reset to the menu (the button, a power cycle) and freeze again.
  System-area facts the dump does not need but explain what is in slot 0: banks 0-7 ROML are the KERNAL images (the eight boot sectors), bank 0 ROMH `$1F00` the trampoline, banks 8-10 menu, `$10` the EF-Directory.
- **Writer, whole-cart erase.** F7 picker last entry "ERASE WHOLE CART..." (behind the slots and "Full EF3 (all slots, type 90)"): popup (what goes: 8 MB, system area, every slot, directory) YES/NO, then the user types the word ERASE (case ignored); any other
  answer ends it with nothing sent. Then (TRX: write guard open, `ROM_WR_EN` restored on every way out, flash reset after a failure) the chip erase `$AA $55 $80 $AA $55 $10` at `$8AAA/$8555` slot 0 bank 0, done when
  `$8000` reads `$FF` twice (DQ7), timeout 300 s, status line counts seconds; then a spot check of the first 16 bytes of both halves of all 512 banks (any byte not `$FF` fails it). The picker at the open of the writer offers slots and Full EF3, not the erase. Slot writes (type 32) still refuse slot 0 except the directory sector.
- **Writer, type 90 image.** The picker choice "Full EF3 (all slots, type 90)" plus a type 90 CRT: F3 asks two questions (popup, typed word WRITE); Full EF3 with a type 32 CRT, or a single slot with a type 90 CRT (writing one slot out of an image is not supported), is refused with a popup and nothing is sent; the CRT is validated first (bank < 512, loads `$8000/$A000/$E000`, packets complete)
  and nothing is touched when it is not valid; the slots the file has packets for are erased (slot 0: eight 8 KiB boot sectors, then the 64 KiB sectors; others: all 64 KiB sectors) and programmed bank by bank; other slots are not
  touched. A file with slot 0 only is the way back after a whole-cart erase (`ef3_image.py new` / `system` make one from skoe's base image). F5 verifies every slot of the file, the banks of such a slot that the file leaves out
  against `$FF`. A type 90 CRT on a cartridge that is not an EasyFlash 3 is refused. EAPI of the image is written as it is (no replacement for type 90).
- Neither the dumper nor the verify writes; erase and image write run only inside the confirmed paths; `s_ef3_system` (slot 0 writable) is set only inside the image write and cleared on every way out.

## 7. Board steps (Alex, real EF3 in the port; one session, nothing destructive without his go)

Needs the app of `t51-ef3-app` (trex_crt.u2a; firmware for the cartridge write-back only if the emulation is tested too).
1. **Full dump (read only).** EF3 in the port, power on (menu showing, EF mode), freeze, start trex_crt Dumper. Picker F7: "All slots (type 90)", F3, YES, pick a folder/name. Wait: 1024 packets, 8.4 MB (time not measured on hardware: 8 MB through DMA reads
   and file writes; the app has no abort key during a dump). Result "Done: 512 banks, 8192KB saved." Dump twice and `cmp` the two files (reads of the same flash must agree).
2. **Compare.** `tools/ef3_image.py info FILE` (8 slots, directory names; slot 0 has the KERNAL names), `tools/ef3_image.py extract FILE N slotN.crt` equals a one-slot dump of slot N from the same session (F7 slot N, F3).
   Slot 0 bank 0 ROMH `$1F00`, banks 8-10 and `$10` should look like the base image (`ef3_image.py info`: "64 of 64 banks not erased" for slot 0 is normal).
3. **Round trip in the emulation.** Put the 8.4 MB file on the C64U (our bitstream, REU off), load it; the C64 boots slot 0 bank 0, i.e. the system area's boot code (the menu needs `$DE0F`, not built here: expect it not to come up; scope item 5 is the open question). With `R2_INIT`
   there is no app setting yet to start slot N. What can be checked on the board: `carts_board.py` `easyflash3` (program, boot-sector erase, 64 KiB erase, chip erase of the loaded image) after `carts.py --emit DIR easyflash3`, and any slot's game loaded as a type 32 CRT (the existing EasyFlash path).
4. **Whole-cart erase: only on his explicit go**, and only with the full dump (twice) saved and the system image (`ef3_image.py` can cut slot 0 out as type 32: `extract FILE 0 sys.crt`; or skoe's base image) at hand. F7, "ERASE WHOLE CART...", YES, type ERASE: the status counts seconds, ends with "Whole cart erased. Write a system image!".
   The cart is blank and does not start. Recovery: `ef3_image.py new -o base.crt --system sys.crt` (slot 0 from the system image, slots 1-7 erased), put the CRT on the stick, trex_crt Writer on it (F7, "Full EF3 (all slots, type 90)"), F3, YES, type WRITE, then F5 verify; the cart should show its menu again.
   Restore of everything: write the full dump (type 90) the same way.

## 9. Risks

- The whole-cart erase and the type 90 write run through DMA writes on a real chip; the code paths follow the EAPI's sequences and the datasheet, they are host-tested against a model of the chip, **not hardware-tested**. A failed slot-0 write leaves the cart without a menu until the image is written again.
- Auto write-back saves an erased emulated image into its CRT file (faithful, scope D5): keep a copy of the base image.
- The dump relies on the EF3 being in EF mode (power-on / menu button). In KERNAL or freezer mode it is not recognised.
- DMA read speed on the real cart (T57 B11: PHI2 stopped between DMA bytes) is untested; the 8 MB dump has no abort key and no read-back check inside the app: dump twice and compare.
